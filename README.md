## 🎯 무엇을 겨냥했나

청년 주거 정책은 대부분 **월세 지원**에 집중돼 있습니다.
부동산 앱도 월세와 보증금으로 매물을 정렬합니다.

그런데 월세를 10만 원 아껴도 출퇴근이 30분 늘어나면, 그 이득은 어디로 갈까요?

**교통비와 시간은 통장에서 빠져나가지 않습니다.** 그래서 계산서에 적히지 않고,
집을 고를 때도 비교 대상이 되지 못합니다.

LOCA는 그 **보이지 않는 청구서**를 숫자로 만들어, 청년이 무엇을 아끼고
무엇을 감수하는지 눈으로 보고 고를 수 있게 하는 서비스입니다.

<br>

### 목표 3가지

| | 목표 | 달성 방법 |
|---|---|---|
| **1** | 월세 외 부담을 정량화한다 | 교통비 + 통근시간 기회비용을 월 단위 금액으로 환산 |
| **2** | 지역 간 실제 부담을 비교한다 | 서울 420개 행정동을 같은 기준으로 순위화 |
| **3** | 개인 조건에 맞춰 추천한다 | **근무지를 입력받아** 그 사람 기준으로 재계산 |

```
통합부담 = 표면주거비 + 월 교통비 + 통근시간 기회비용
          (월세 + 보증금 월환산)  (정기권 상한 적용)  (최저임금 환산)
```

## 🖥️ 어떤 서비스인가

거주지·근무지·만 나이·보증금·월세를 입력하면, **현재 부담을 진단하고 대안을 비교**합니다.

```
   ┌─────────────┐      ┌─────────────┐      ┌─────────────┐      ┌─────────────┐
   │  ✍️  입력   │  →   │ 📊 현재 진단   →   │ 🔎 대안 탐색 │  →  │ 📋 상세 비교 │
   ├─────────────┤      ├─────────────┤      ├─────────────┤      ├─────────────┤
   │ 거주지·근무지│      │ 부담 구성비  │      │ 후보 검증    │     │ 4개 지역     │
   │ 만 나이      │     │ 통근 경로    │      │ 추천 3곳     │     │ 나란히 비교  │
   │ 보증금·월세  │      │ 지역 유형    │      │ 총부담 증감  │     │ 차트·표      │
   └─────────────┘      └─────────────┘      └─────────────┘      └─────────────┘
```

<br>

### 주요 기능

**📊 현재 부담 진단**
입력한 조건으로 월 총부담을 계산하고, 주거비·교통비·시간가치 구성비를 보여줍니다.
통근 경로와 이용 노선을 실제 노선색으로 표시하고, 그 동네가 6유형 중 어디에
속하는지 진단합니다.

**🔎 대안 탐색**
후보 지역을 입력하면 현재 집과 비교해 **월세 착시 / 실질 절감 / 숨은 효율 /
종합 부담 증가** 중 어디에 해당하는지 판정합니다. 동시에 같은 근무지 기준으로
총부담이 낮은 3곳을 추천합니다.

**📋 상세 비교**
현재 집과 후보 3곳을 한 표에 놓고 주거비·통근시간·교통비·환승·총부담을
나란히 비교합니다. 부담 구성을 누적 막대로 시각화합니다.

**🔍 어떤 입력이든 받는 검색**
카카오 로컬 API로 역명·건물명·도로명·지번을 모두 행정동으로 해석합니다.

```
신사샤르망S 오피스텔  →  잠원동        시청역        →  소공동
삼정KPMG            →  역삼1동       테헤란로 152  →  역삼1동
```

**🎫 만 나이 기반 교통비 적용**
만 19~39세는 모두의카드 청년 기준(55,000원), 그 외는 일반 기준(62,000원)이
자동 적용되고 화면에 사유가 표시됩니다.

<br>

### 분석 4단계

**1️⃣ 업무지구 판정**
"업무지구가 어디인가"는 한 축만 보면 오판합니다. 규모만 보면 큰 주거지가 섞이고,
주야간 인구비만 보면 작은 상업지가 올라옵니다. **규모·방향·시간 3축**으로
판정해 55개 동을 뽑고, 상업지·대학가·R&D 단지 등 15개를 사유와 함께 제외해
**9개 지구 40개 동**을 확정했습니다.

**2️⃣ 통합부담 테이블**
420개 행정동의 주거비·교통비·시간가치를 합산하고, 주거비 순위와 통합부담 순위의
차이로 **부담 4유형(A 실질저부담 / B 월세착시 / C 숨은효율 / D 종합고부담)**을
분류했습니다.

**3️⃣ 행정동 유형화 (군집)**
부담 블록과 이동구조 블록을 **50:50으로 균형**을 맞춰 FuzzyCMeans로 6유형을
도출했습니다. 소속 확률을 함께 산출해, 경계가 모호한 63개 동(15%)은
"두 유형 성격을 함께 가짐"으로 표시할 수 있게 했습니다.

**4️⃣ 근무지별 개인화 (SQL Q1~Q7)**
9개 업무지구별로 최적 거주지를 다시 계산하고, 주거비 절감분이 통근으로
되돌아가는 **상쇄율**을 지구별로 산출했습니다.

<br>

### 📈 추가 발견

**부담 구성비는 주거비 69.9% / 통근부담 30.1%** (중앙값)
주거비 순위와 통합부담 순위의 스피어만 상관은 **0.967**이지만,
**50계단 이상 순위가 뒤바뀐 동이 63개(15.0%)** 있었습니다.

**근무지가 부담 수준 자체를 결정합니다.**
최저 통합부담이 강남 근무 **81.9만원** vs 구로·가산 근무 **66.3만원**으로
약 16만원 차이가 났습니다. "어디 사느냐"보다 "어디서 일하느냐"가 먼저입니다.

**청년은 비싸도 가까운 곳에 삽니다.**
군집에 넣지 않은 변수인데도 유형별로 2배 이상 갈렸습니다.
고주거비·직주근접형 **27.9%** vs 주거절감·장거리통근형 **12.6%**
(Kruskal-Wallis H=65.85, p<0.001)

> ## 🔑 결론
>
> 저희 가설은 "월세가 싸 보이는 동네가 사실은 아니다"였습니다.
> 그런데 데이터는 다른 답을 줬습니다. **월세 착시가 실제로 나타난 곳은 420개 중 14곳(3.3%)뿐**이고,
> 주거비 순위와 통합부담 순위의 상관은 **0.967**이었습니다. 대부분은 싼 동네가 실제로도 유리했습니다.

> 그래서 결론은 "월세만 보지 마세요"가 아니라

## 🔍 신뢰할 수 있는가

숫자를 만드는 것보다 **그 숫자를 믿을 수 있는지 확인하는 데** 더 많은 시간을 썼습니다.

**99.4%는 정확도가 아니라 채움률이었습니다.**
행정동 매칭률을 그대로 적었다가, 도로명만으로 조회하면 그 도로 위 임의 주소가
반환된다는 걸 발견했습니다. 최소 467개 도로가 복수 행정동에 걸칩니다.
정답을 아는 거래 **5,821건**으로 역산해 실제 정확도를 구하고, 신뢰도 등급을
만들어 화면에 표시했습니다.

**생활소비부담지수는 산출에 성공했지만 핵심 지표에서 뺐습니다.**
업무중심성과 상관 0.38로 거주자 소비가 아닌 상권 규모를 재고 있었습니다.
가설 4개를 실험해 **시간대가 아니라 연령이 분리 축**임을 확인하고 편향을 43.7%
줄였지만, 건당 결제금액이 가격인지 소비량인지 분리할 수 없어 제외했습니다.

**k=6은 통계적 최적값이 아닙니다.**
실루엣만 보면 k=3이 높지만 한 군집에 194개 동이 묶여 이동구조 차이가 사라집니다.
분리도·최소 군집 크기·안정성을 함께 보고 절충했습니다.

**설계에서 지킨 것**
없는 데이터를 좋은 값으로 읽지 않습니다(요금 결측을 0이 아닌 상한으로 대체).
추정한 값은 추정했다고 밝힙니다(경로 대체 시 화면 표시).
믿을 수 없는 값에는 라벨을 붙입니다(`unreliable` 4곳, `low_confidence` 26곳).

## 🚀 실행

### 🐳 Docker (권장)

MySQL 8.0 과 Flask 를 한 번에 띄웁니다. 로컬에 MySQL 이나 Python 이 없어도 됩니다.

```bash
cp .env.example .env        # MYSQL_PASSWORD 만 채우면 됩니다
docker compose up -d --build
```

| | |
|---|---|
| 서비스 | http://127.0.0.1:5000 |
| DB | `127.0.0.1:3307` (로컬 MySQL 과 겹치지 않게 3307) |

기동하면 `sql/init/` 이 자동으로 실행돼 **테이블 15개 + 뷰 2개**가 만들어집니다.
파라미터 시드(시간가치·소득 시나리오·생활비 가정)도 함께 들어갑니다.

```bash
docker compose exec db mysql -u root -p multicam -e "SHOW FULL TABLES;"
```

**데이터 적재는 포함하지 않습니다.** 원본 CSV 가 저장소에 없고, 57만 행 적재를
기동에 넣으면 `docker compose up` 이 수십 분 걸립니다. 환경을 세우는 일과
데이터를 넣는 일을 분리했습니다. 적재는 아래 3~4단계를 컨테이너 안에서 돌립니다.

```bash
docker compose exec web python src/db/load_to_db.py
docker compose exec web python src/db/run_sql.py sql/load/01_dong_reliability.sql
docker compose exec web python src/db/run_sql.py sql/load/02_fallback_candidate.sql
```

<br>

### 직접 실행

```bash
# 1. 환경  (Python 3.13)
pip install -r requirements.txt
cp .env.example .env        # MySQL 접속 정보 입력

# 2. 스키마 + 파라미터  (데이터 의존 없음)
python src/db/run_sql.py sql/init/01_schema.sql
python src/db/run_sql.py sql/init/02_seed_params.sql
python src/db/run_sql.py sql/init/03_transport_pass_assumption.sql

# 3. 적재
python src/db/load_to_db.py

# 4. 서비스용 테이블  (FK가 dim_region 을 참조하므로 적재 후)
python src/db/run_sql.py sql/load/01_dong_reliability.sql
python src/db/run_sql.py sql/load/02_fallback_candidate.sql

# 5. 검증  (QC 14종)
python src/db/run_sql.py sql/qc/01_qc.sql
python src/db/run_sql.py sql/qc/02_qc_transport_pass.sql

# 6. 서비스
python web/app.py           # http://127.0.0.1:5000
```

**2단계와 4단계를 나눈 것이 중요합니다.** `sql/load/` 의 두 파일은 FK 가
`dim_region(dong_code8)` 을 참조하는데, `dim_region` 은 3단계에서 채워집니다.
순서를 바꾸면 FK 위반으로 실패합니다.

원본 데이터는 용량 문제로 저장소에 포함하지 않았습니다.
받는 곳과 두는 위치는 [`data/README.md`](data/README.md) 참고.

## ⚠️ 알려진 한계

**표면주거비 행정동 배정** — 단독다가구는 지번이 마스킹돼 정밀 배정이 구조적으로 불가능합니다.
신뢰도 등급으로 표시하되, 지번 우선 알고리즘으로 교체하는 것이 다음 과제입니다.

**경로 커버리지** — 거주동별 누적 80% 목적지만 TMAP을 호출해, 흐름이 적은 조합은 빠져 있습니다.
입력 단계에서 갈 수 있는 곳만 제안하는 방식으로 대응했습니다.

**통근권 모듈러리티 0.308** — 서울 통근이 도심·강남으로 수렴해 강하게 분리되지 않습니다.
"뚜렷한 경계"가 아니라 "느슨한 묶음"으로 해석해야 합니다.

**인과관계 미검증** — "청년이 직주근접을 선호한다"는 분포 관찰이지 인과 증명이 아닙니다.
