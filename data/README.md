# data/ — 파이프라인이 읽고 쓰는 곳

## 저장소에 없는 것

원본 CSV와 중간 산출물은 **합계 1.7GB**라 저장소에 포함하지 않았습니다.
전부 공개 데이터라 아래에서 다시 받을 수 있습니다.

**여기 있는 파일은 두 종류입니다.**

- **참조표 8종** — 크기가 작고, 이게 없으면 파이프라인이 아예 돌지 않습니다
- **분석 산출물** — 재현 검증에 쓰이는 소용량 결과물

`docs/` 와의 구분은 [`docs/README.md`](../docs/README.md) 참고. 요약하면
**`data/` 는 코드가 읽고 쓰는 것, `docs/` 는 사람이 근거로 읽는 것**입니다.


## 실행 순서

원본을 받아 위 위치에 두었다면, 이 순서로 돌아갑니다.

```bash
python src/reference/build_region_master.py      # 기준코드표 (이미 포함됨)
python src/preprocessing/...                      # 실거래가 정제 → 행정동 배정
python src/indicators/...                         # 표면주거비 · 생활소비부담지수
python src/analysis/define_business_districts.py  # 업무지구 판정
python src/analysis/build_total_burden.py         # 통합부담 테이블
python src/db/load_to_db.py                       # MySQL 적재
```

각 단계 상세는 해당 폴더 README를 보세요.

**`build_total_burden.py` 는 `--dry-run` 을 먼저 돌리는 것을 권합니다.**
기존 산출물과 자동으로 대조해 부담유형 A/B/C/D 분포가 얼마나 흔들리는지
보여줍니다. 서비스 추천 결과가 여기서 갈립니다.

## 격리 폴더

`data/quarantine/` 에는 **기준표에 없는 코드 때문에 적재에서 빠진 행**이 쌓입니다.

버리지 않고 따로 남기는 이유는, 빠진 행이 몇 건인지 알아야 그게 정상인지
버그인지 판단할 수 있기 때문입니다. 실제로 OD 828건, 경로 203건,
실거래 16건이 격리됐고 전부 폐지 코드로 확인됐습니다.

진단은 `python src/db/check_quarantine.py` 로 합니다.

## 주의

**중간 산출물을 수기로 편집하지 마세요.** 값이 이상하면 만든 스크립트를 고쳐
다시 돌립니다. 여기서 손대면 다음 재실행 때 되돌아가고, 그 사이에 만든
DB 적재본과 어긋납니다.

**파일명에 날짜를 붙이지 마세요.** 백업이 필요하면 파이프라인 스크립트가
`_YYYYMMDD_HHMM.bak.csv` 로 자동 생성합니다. 수동 백업본은 `.gitignore` 대상입니다.
