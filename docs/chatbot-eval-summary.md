# 챗봇 답변 평가 요약

LOCA 챗봇이 화면의 계산 결과와 방법론 문서를 설명할 때, 없는 값이나 없는
근거를 지어내지 않는지를 측정한 기록이다. 실행별 원본 표는 이 문서 아래와
`docs/eval/doc-search-eval.md` 에 이어붙는다.

- 답변 평가: `python scripts/run_chat_eval.py` (골든셋 24문항)
- 검색 평가: `python scripts/run_doc_eval.py` (골든셋 22문항)
- 실패 상세: `python scripts/show_eval_detail.py --axis citation`

## 2. 실행 환경이 모델을 결정했다

| 모델 | 결과 |
|---|---|
| exaone3.5:7.8b | 컨텍스트를 읽는 것만으로 240초 초과. CPU 로는 사용 불가 |
| exaone3.5:2.4b | 문항당 20~90초. 채택 |

GPU(GTX 1060 3GB)는 VRAM 부족으로 7.8B 를 올리지 못한다. 드라이버는 최신
(560.94 / CUDA 12.6)이라 업데이트로 해결되는 문제가 아니다.

작은 모델을 쓸 수 있었던 이유는 검증 계층이 먼저 있었기 때문이다. 모델이
틀리면 게이트가 막고 템플릿 답변으로 내려간다. **모델 품질은 답변의
유용성을 결정하지만 정확성을 결정하지는 않는다.**

제공자는 환경변수 한 줄로 바뀐다(`LLM_PROVIDER=anthropic`). 프롬프트·게이트·
폴백·골든셋은 그대로다.

## 3. 구조로 해결한 것

### 원 단위 노출 제거 — numbers 8 → 23/24

초기에 20문항 중 12건이 게이트에 막혔고, 사유가 거의 하나였다.

```
원문: "주거비가 795만원입니다"        화면: 79.5만원
원문: "총합은 약 1,306만7천원입니다"   화면: 130.7만원
```

컨텍스트에 원 단위와 만원 표기를 **둘 다** 넣은 것이 원인이었다.

```json
{"housing_won": 795000, "display": {"housing": "79.5"}}
```

프롬프트로 "display 를 쓰라"고 지시해도 모델은 앞의 숫자를 집었다. 그래서
프롬프트에 실을 때 `_won` 으로 끝나는 키를 전부 제거했다.
**보여 주지 않으면 말할 수 없다.** 차단이 12건에서 0~1건으로 줄었다.

컨텍스트 자체는 원 단위를 유지한다. 폴백 문장과 허용 숫자 집합이 그 값을
쓰기 때문이다. 프롬프트에서만 가린다.

### 단위를 표시 문자열에 포함

`"10.8"` 만 주니 모델이 `"10.8시간"` 이라고 답했다. 실제로는 10.8만원이다.
숫자가 맞아서 게이트를 통과했다 — **숫자 게이트는 단위를 보지 못한다.**

`display` 값에 단위를 넣어(`"10.8만원"`, `"17.2분"`) 붙일 일 자체를 없앴다.
원 단위 제거와 같은 방법이다.

### 거절 사유를 프롬프트 맨 앞으로

거절해야 할 문항이 전부 실패했는데, 사유는 모두 컨텍스트에 있었다. 작은
모델이 긴 JSON 가운데의 `unknown` 배열을 못 본 것이다. 목록으로 꺼내
질문 바로 다음에 놓았다.

단서(`candidate_housing_basis`)는 거절 사유와 분리했다. 섞어 두면 비교
질문까지 거절한다.

### 문서를 못 찾은 사실도 컨텍스트에 싣는다

방법론 질문인데 검색 결과가 없으면 `unknown` 에 `doc_not_found` 를 넣는다.
빈 목록만 주면 모델은 문서가 없다는 것을 모른 채 이유를 지어낸다.

## 4. 게이트가 막는 것과 막지 못하는 것

막는다.

- 컨텍스트에 없는 숫자 (10배 오독, 직접 계산한 값)
- 한국어가 아닌 답변, 한자 혼입
- 형식이 깨진 출력

막지 못한다. 네 종류 모두 실제 답변에서 나왔다.

| 유형 | 실제 사례 | 왜 못 잡나 |
|---|---|---|
| 맞는 숫자, **틀린 대상** | "청림동의 총부담은 97.4만원" (현재 집 값) | 컨텍스트에 존재하는 숫자 |
| 맞는 숫자, **틀린 비교** | "79.3만원으로 76.8만원보다 낮습니다" | 값은 맞고 대소 판단이 틀림 |
| 맞는 숫자, **틀린 단위** | "통근시간 가치 10.8시간" | 숫자만 검사 → **구조로 해결함** |
| **숫자 아닌 환각** | "환승 없는 후보로 신길제3동"(환승 1회), "신림동동" | 숫자가 없음 |

이 게이트는 "없는 값을 만들어내는 것"을 막지 "잘못 배치하거나 잘못 비교하는
것"은 막지 못한다. 후자는 골든셋 평가에서 사람이 답변 원문을 읽고 판단한다.

## 5. 모델에 남은 한계

거절 실패 5건은 모두 사유가 컨텍스트에 있는데도 답을 만들어냈다.

| 문항 | 물어본 것 | 있어야 할 답 |
|---|---|---|
| p4-02 | 통근시간 짧은 순으로 정렬해줘 | 화면 조작은 할 수 없음 |
| p4-03 | 이 지역은 왜 많이 찾는 후보인가 | 인기도 자료 없음 |
| p5-03 | 이사하면 얼마나 저축되나 | 소득을 입력받지 않음 |
| p6-03 | 혼잡까지 고려하면 어디가 나은가 | 혼잡도 자료가 일부 구간만 존재 |
| cm-03 | 판교로 이사하면 어떤가 | 분석 범위는 서울시 행정동 |

이 5건이 전부 **화면에 실제로 있는 질문 칩**이다. 답할 근거가 없는 질문을
화면이 먼저 권하고 있다. 모델 교체와 별개로 칩 문구 재검토가 필요하다.

## 6. 검색은 왜 따로 재는가

검색이 엉뚱한 문서를 가져오면 모델은 그것을 성실하게 요약한다. 그 답변은
숫자 게이트를 통과한다 — 가져온 문서에 실제로 있는 숫자이기 때문이다.
**답변 게이트로는 원리적으로 막을 수 없는 자리라 검색 단계에서 막아야 한다.**

그래서 답변을 만들기 전에 검색만 따로 채점하고, 답변 평가에는 `doc` 축을
두어 "문서가 기대대로 붙었는가"를 분리했다. 답변이 나쁠 때 검색이 못 찾은
것인지 모델이 못 쓴 것인지 구분해야 고칠 데를 안다.

### 설계 선택

- **BM25 + 글자 2-gram.** 조각 60개 규모에서 임베딩은 얻는 것보다 드는 것이
  많다. 점수의 근거가 "어떤 단어가 몇 번 맞았는가"라 디버깅이 되고,
  그래야 검색 문제와 모델 문제를 갈라낼 수 있다.
- **근거가 없으면 빈 목록.** 최소 점수와 최소 일치 수를 둬서 관련 없는
  질문에는 아무것도 돌려주지 않는다. 점수가 낮아도 뭔가 주는 검색기는
  환각의 재료를 만든다.
- **질문 기능어 제거.** "어떻게", "왜" 같은 말은 문서에 드물어 IDF 가 높게
  잡히는데 의미는 없다. 이것 때문에 무관한 문서가 1위로 올라온 적이 있다.
- **청킹은 헤딩 기준 + 작은 조각 병합 + 표 보존.** 이 문서들은 표에 결론이
  들어 있어 표가 갈리면 조각 양쪽 다 쓸모없어진다.

### 남은 오탐 1건

"이 서비스 만든 사람 연봉이 얼마예요?" 가 문서에 걸린다. `서비스`·`사람`·
`얼마` 가 실제로 문서에 있기 때문이다. 점수와 맞은 토큰 수 모두 정답 분포
한가운데라 임계값으로 가를 수 없다. **어휘 검색은 단어가 맞았는지만 알지
주제가 맞는지는 모른다.** 현재 화면에 자유 입력창이 없어 실제 발생 경로는
없지만, 입력창을 열거나 임베딩으로 바꿀 때의 비교 기준으로 남겨 둔다.

## 7. 검색이 드러낸 문서 공백

검색 골든셋을 처음 돌렸을 때 두 질문이 "근거 없음"으로 나왔다. 검색기
문제가 아니라 **답할 문서가 없었다.**

- 보증금을 왜 월세로 환산했나요? → 전월세전환율 근거가 코드·테스트에만 있음
- 표본이 적은 동은 어떻게 표시하나요? → 신뢰도 판정 기준이 CSV 로만 있음

둘 다 화면에 값이 떠 있는데 설명이 없는 부분이었다. 코드의 실제 값과 주석을
근거로 문서 두 편을 작성해 메웠고(`보증금_월환산_근거.md`,
`표본_신뢰도_표시_근거.md`), 오탐 1건도 함께 사라졌다.

## 8. 평가 도구에서 발견한 오류

측정값을 믿기 전에 측정 도구를 검증하는 과정에서 일곱 건을 찾았다.
모두 실제 점수를 왜곡하고 있었다.

| 오류 | 증상 | 영향 |
|---|---|---|
| 폴백을 채점 | 게이트가 막은 문항이 PASS 로 집계 | 40% → 실제 20% |
| 평가 기록이 색인에 포함 | 골든셋 질문이 적힌 파일이 모든 질문에 1위 | recall@1 93% → 14% |
| 온도 0.2 | 같은 코드로 재실행해도 결과가 달라짐 | 개선인지 흔들림인지 구분 불가 |
| 사본 파일 색인 | 같은 내용 24조각 중복 | 검색 상위가 원본·사본으로 채워짐 |
| 서수 오탐 | 목록 번호 "2)" 를 지어낸 숫자로 판정 | 정상 답변 2건 차단 |
| 경로 표기 오탐 | `[문서#01]`, `candidates[0]`, `home.candidates` 를 없는 경로로 판정 | citation 9 → 16 |
| 거절 사유 단일 정답 | 맞는 사유가 여럿인데 하나만 인정 | 옳은 거절이 감점 |

첫 번째가 가장 컸다. 폴백 문장은 화면 값을 그대로 나열하므로 근거 인용
기준을 항상 만족한다. 차단된 답변이 통과로 집계되고 있었다.

두 번째는 자기 참조였다. 평가 기록에 골든셋 질문 20개가 표로 적혀 있어,
그 파일이 색인에 들어가자 모든 평가 질문에 완벽하게 매칭됐다. 지금은
파일명·내용·폴더 세 겹으로 막고 평가 산출물을 `docs/eval/` 아래에 쓴다.

세 번째를 고치기 전까지의 모든 비교는 신뢰할 수 없었다. 온도를 0 으로
고정하고 두 번 실행해 결과가 완전히 일치하는 것을 확인한 뒤에야 숫자를
신뢰할 수 있었다.
