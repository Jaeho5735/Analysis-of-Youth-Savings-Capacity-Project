# 디버깅 이력 — 전처리 (src/preprocessing/)

법정동을 행정동으로 붙이는 과정에서 겪은 문제와, 외부 코드 리뷰로 잡은 결함을 정리한다.

## 왜 이걸 남기는가

이 단계의 버그는 **에러를 내지 않는다.** 잘못 붙어도 프로그램은 정상 종료하고, 결과 파일도 멀쩡해 보인다. 그래서 "매칭 성공"으로 위장된 오염을 나중에야 발견했다.

> **조용히 실패하는 결합은 시끄럽게 실패하는 결합보다 위험하다.**

## 1부. 표기 변이 8라운드

### 발단

`표면주거비_행정동별.csv`에 **"가양1동"과 "가양제1동"이 따로** 들어 있었다. 같은 동인데 두 행으로 쪼개져 169쌍이 나왔다.

원인은 경로에 따라 이름이 다르게 들어온 것이었다.

| 경로 | 표기 |
|---|---|
| KIKmix 텍스트 매칭 | "가양**제**1동" |
| 카카오·juso API | "가양1동" |

### 라운드별 기록

| # | 증상 | 원인과 조치 |
|---|---|---|
| 1 | "가양1동" vs "가양제1동" 169쌍 | `resolve_precise_jibun.py`에 정규화 함수 추가, 공식 목록 대조로 "제" 유무 보정 |
| 2 | 가양2·3동 같은 **진짜 동이 누락** | 공식 목록을 `lookup`의 **대표값 픽 결과**로 만든 것이 원인. `code_df` 원본 읍면동명 **전체**에서 추출하도록 수정 |
| 3 | 정규화 후 432개 (목표 초과) | "성수1가1동"처럼 중간에 숫자가 낀 이름을 정규식이 포기. `(.+?)([\d.]+동)$`로 완화 |
| 4 | 여전히 초과 | "면목3.8동"처럼 점이 낀 합성동. `[\d.]+` 적용 |
| 5 | **가장 치명적** | 공식 목록이 **전국 단위**여서, 서울 밖에 우연히 존재하는 동명이인("가양1동") 때문에 정규화가 "이미 맞는 이름"으로 조기 판단. **서울로 한정**해 426개 수렴 |
| 6 | 초과 | "금호2.3가동", "종로1.2.3.4가동" 같은 "가"까지 낀 복합동. `[\d.]+가?동`으로 확장 |
| 7 | 시계열 손실 | **2026년 상권분석 파일에서만** 마침표(U+002E)가 물음표(U+003F)로 손상. `(\d)\?(\d)`로 고쳤더니 **연속 물음표를 절반만 처리해 재발**. `(?<=\d)\?(?=\d)` lookaround로 완전 해결 |
| 8 | 행 분할 | 상계3·4동 등 7개가 마침표 대신 **가운뎃점(U+00B7)** 사용. 정규화 미통과로 "·판"과 ".판" 두 행으로 갈림. 양쪽 다 반영업종수 9~10이라 **시계열 손실이 유의미**했음. 숫자 사이 중점류 7종 → 마침표 치환 추가 |

8라운드 재실행 결과 정규화 431→424, 행정동 425개 수렴, 매칭 실패 5건 동일(회귀 없음).

### 남은 5개 동

신설동·용두동·개포3동·상일제1·2동. 이건 **표기 문제가 아니라 실제 행정동 개편**이다.

| 남은 동 | 반대편 짝 |
|---|---|
| 신설동, 용두동 | 용신동 (2025-07-01 분동으로 폐지) |
| 상일제1·2동 | 상일동 (2021-07-01 분동 전) |
| 개포3동 | 일원2동 (2022-12-23 개칭) |

`src/reference/`의 폐지코드 매핑으로 해결한다.

### 교훈

정규화는 "고쳤다"로 끝나지 않는다. **정규화 후 공식 목록에 없는 잔여분을 매번 세는 진단**을 상시 두어야 다음 변이가 드러난다.

## 2부. 외부 코드 리뷰 4라운드

### 1차 — 5건 지적

**오류 1 (가장 심각) — 동명이인 오염**

이름만으로 merge하면 신사동(강남구·관악구·은평구)이 섞인다. 문제는 **이게 "매칭 성공"으로 위장된다**는 점이다. 에러가 안 나니 아무도 모른다.

→ `dong_matcher.py`가 `(시군구명, 행정동명, 행정동코드)` 3컬럼 참조표를 만들고, **(구, 동) 조합**으로 `행정동코드_최종`을 재조회하도록 수정. 상권분석(8자리)과 KIKmix(10자리)는 앞 5자리 시군구코드로 구를 역산해 결합.

**오류 2 — 군집화용 행정동당 1행이 없었다**

유형별 3행만 있었고, 유형별 중앙값을 단순 평균하면 표본 가중치를 무시한다. → 개별 거래에서 직접 pooled 중앙값을 내는 `표면주거비_행정동_통합.csv` 신규 생성.

**오류 3 — 연월 산술 버그**

`nearest_month_rate`가 YYYYMM 정수 뺄셈이라 **12월↔1월 차이를 89로 계산**했다. → "연×12 + 월" 인덱스로 수정.

**오류 4·5** — z-score 극단치 취약(클리핑 추가), 지수만 통짜 평균(`생활소비부담지수_최근1년` 병기 + 민감도 로그).

### 2차

**HIGH1 — z-score 오염**

mean/std를 계산한 **뒤에** 클리핑하는 것은 이미 오염된 통계량이라 무의미하다. → median/MAD(1.4826) 강건 z-score로 교체.

검증하니 상위 10 중 **4개만 유지**됐고 청담동이 1.58 → 3.02로 바뀌었다. **오염이 순위를 실제로 왜곡하고 있었음이 수치로 확인**됐다.

**HIGH2** — 최종 merge에 `validate="many_to_one"` 추가.
**MEDIUM** — `code_changed` 카운트가 float 잔재("1234.0" vs "1234")로 부풀려지던 버그, `행정동코드_최종` 결측 탈락 행수 로그 추가.

### 3차 — 잘못된 해결책 되돌리기

2차에서 넣은 dedup("반영업종수 많은 쪽만 남김")이 **오히려 틀렸다.** (구, 동)이 같고 코드만 다른 건 대부분 **코드 개편 전/후 시기**라, 한쪽을 버리면 시계열 절반을 폐기하는 셈이었다.

→ `build_index` 집계 키에서 `행정동_코드`를 빼고 `(시군구명, 행정동_코드_명)`만으로 groupby해 자연 풀링. dedup 로직 삭제.

**MEDIUM** — median/MAD는 오염을 막지만 극단 동네 **자신의** 점수는 커질 수 있다(MAD < std라 분모 축소). → "median/MAD 계산 후 ±3 클리핑" 결합으로 완성. 방식 ①②③ 비교표 자동 출력.

### 4차 — 정체성 정의 변경의 파급

정체성을 `(시군구명, 행정동명)`으로 바꿨는데 **파일 간 dedup만 옛 기준**(`행정동_코드`)에 남아 이중 카운트 위험이 있었다. → 새 정체성 기준 진단 + 재중복제거(`keep="last"`) 추가. 재실행 결과 0건으로 실피해는 없었음이 확인됐다.

### 여기서 나온 원칙
