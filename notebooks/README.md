## `01_preprocess_youth_single_household.ipynb`

### 목적

서울시 자치구별 주민등록 1인세대 원본 파일을 불러와 행정동별 청년 1인세대수를 계산하고, 연도별 통합 데이터를 생성한다.

청년 연령 범위는 원자료의 연령 구간을 기준으로 20~39세로 정의했다.

### 사용 데이터

- 서울시 주민등록 연령별 1인세대 현황
- 2023년, 2024년, 2025년 자료
- 연도별 자치구 단위 Excel 파일

### 주요 전처리

1. 연도별 폴더에서 Excel 파일 목록을 불러온다.
2. 서울 전체 합계 파일은 제외하고 자치구별 파일만 처리한다.
3. 파일마다 실제 컬럼명이 시작되는 위치가 다를 수 있으므로, `행정기관코드`가 포함된 행을 찾아 헤더로 사용한다.
4. 전체 값이 비어 있는 행과 열을 제거한다.
5. 컬럼명의 줄바꿈, 앞뒤 공백 등 불필요한 문자를 정리한다.
6. 파일마다 달라질 수 있는 컬럼명을 공통 컬럼명으로 통일한다.
7. 행정기관코드는 문자열로 읽어 코드 앞자리와 자릿수가 유지되도록 한다.
8. 숫자 컬럼에 포함된 쉼표를 제거하고 수치형으로 변환한다.
9. 행정구역명에서 시도, 자치구, 행정동을 분리한다.
10. 서울시 전체 및 자치구 합계 행을 제외하고 실제 행정동 행만 남긴다.
11. 다음 연령대의 1인세대수를 합산한다.

```text
20~24세
+ 25~29세
+ 30~34세
+ 35~39세
= 청년1인세대수
```

12. 자치구별 데이터를 하나로 합쳐 연도별 서울시 행정동 데이터를 만든다.
13. 연도별 결과를 다시 합쳐 2023~2025년 통합 데이터를 생성한다.

### 검증

청년 1인세대수를 구성하는 연령대별 값의 합이 원자료의 연령구간 총합과 일치하는지 확인했다.

```text
합계차이
= 원자료 총연령구간세대수 - 연령대별 재계산 값
```

실행 결과에서 합계차이가 발생한 행은 확인되지 않았다.

또한 연도별 처리 파일 수, 행정동 수, 결측치 및 행정기관코드 중복 여부를 확인했다.

### 주요 의사결정

청년 범위는 20~24세, 25~29세, 30~34세, 35~39세 데이터를 합산한 20~39세로 설정했다.

자치구 합계 행은 지역 단위가 행정동이 아니므로 제거하고, 이후 다른 데이터와 결합할 수 있도록 행정기관코드를 기준 식별자로 유지했다.

### 산출물

```text
2023_서울시_행정동별_청년1인세대수.csv
2024_서울시_행정동별_청년1인세대수.csv
2025_서울시_행정동별_청년1인세대수.csv
2023_2025_서울시_행정동별_청년1인세대수.csv
```

## `02_calculate_youth_single_household_share.ipynb`

### 목적

행정동별 청년 1인세대수를 전체 세대수와 결합하여 `청년1인세대비중`을 계산한다.

### 사용 데이터

- `01_preprocess_youth_single_household.ipynb`에서 생성한 청년 1인세대수 데이터
- 서울시 주민등록 전체 세대 및 인구 현황
- 2023년, 2024년, 2025년 자료

### 주요 전처리

1. 전체 세대현황 파일을 불러온다.
2. 행정구역 문자열에서 10자리 행정기관코드를 추출한다.
3. 행정구역명을 시도, 자치구, 행정동으로 분리한다.
4. 서울특별시 자료만 남긴다.
5. 서울시 전체와 자치구 합계 행을 제외하고 행정동 행만 남긴다.
6. 연도별로 가로 방향에 저장된 전체세대수와 전체주민등록인구를 세로 방향 데이터로 변환한다.
7. 연도 컬럼의 자료형을 정리한다.
8. 청년 1인세대수 데이터에서 연령별 값을 다시 합산하여 기존 `청년1인세대수`와 일치하는지 확인한다.
9. 두 데이터에서 `연도 + 행정기관코드` 중복 여부를 확인한다.
10. 청년 1인세대 데이터와 전체 세대현황을 다음 키로 병합한다.

```text
연도 + 행정기관코드
```

11. 병합 전후 행 수와 병합되지 않은 행을 확인한다.
12. 다음 산식으로 청년 1인세대 비중을 계산한다.

```text
청년1인세대비중
= 청년1인세대수 / 전체세대수
```

13. 비중을 해석하기 쉽게 백분율 컬럼도 함께 생성한다.

### 검증

실행 결과에서 다음 사항을 확인했다.

- 청년 1인세대수 재계산 불일치 없음
- `연도 + 행정기관코드` 중복 없음
- 병합 전후 청년 데이터 행 수 동일
- 전체세대수가 병합되지 않은 행 없음
- 전체주민등록인구가 병합되지 않은 행 없음
- 전체세대수가 0이거나 결측인 행 없음
- 계산된 비중이 0 미만 또는 1 초과인 행 없음

### 주요 의사결정

청년 1인세대 비중의 분모는 전체 인구가 아니라 전체세대수를 사용했다.

청년 1인세대수는 세대 단위 값이므로 전체주민등록인구를 분모로 사용하면 분자와 분모의 단위가 달라진다.

따라서 다음과 같이 세대 단위를 일치시켰다.

```text
청년 1인세대 수 / 전체 세대 수
```

### 산출물

행정동별로 다음 변수를 포함한 결과를 저장한다.

```text
연도
행정기관코드
시도
자치구
행정동
청년1인세대수
전체세대수
전체주민등록인구
청년1인세대비중
청년1인세대비중_퍼센트
```

## `03_inspect_youth_mobility.ipynb`

### 목적

청년 연령대 이동데이터의 구조와 품질을 확인하고, 이후 청년 이동 패턴 분석에 사용할 수 있도록 전처리 기준을 정한다.

이 노트북은 본격적인 OD 집계 전에 원자료를 점검하기 위한 탐색 및 진단 단계다.

### 사용 데이터

- 청년 연령대 생활이동 데이터
- 월별 또는 기간별 이동 원본 파일

### 주요 전처리 및 점검

1. 데이터 폴더 안의 파일 목록을 불러온다.
2. 파일명, 파일 개수 및 파일 크기를 확인한다.
3. 샘플 파일을 먼저 읽어 컬럼 구조를 확인한다.
4. 파일별 컬럼 구성이 동일한지 비교한다.
5. 다음 핵심 컬럼의 자료형과 값을 확인한다.

```text
출발 행정동 코드
도착 행정동 코드
연령대
요일
시간대
이동량
이동시간
이동거리
```

6. 행정동 코드는 문자열로 처리하여 코드 손실을 방지한다.
7. 이동량, 이동시간, 이동거리는 수치형으로 변환한다.
8. 연령대 코드와 시간대 코드의 고유값 및 빈도를 확인한다.
9. 주요 컬럼의 결측치를 확인한다.
10. 출발지 또는 도착지가 없는 행이 존재하는지 확인한다.
11. 이동량이 0 이하인 행을 확인한다.
12. 이동시간 또는 이동거리가 음수인 행을 확인한다.
13. 이동시간과 이동거리의 기초통계와 극단값을 확인한다.
14. 동일한 출발동·도착동·시간대 조합의 중복 여부를 점검한다.
15. 월별 파일 사이에 컬럼 구조나 값 범위 차이가 있는지 확인한다.

### 주요 의사결정

청년 이동데이터에는 연령 정보가 포함되어 있지만, 이동 목적이 명확하게 구분되지 않는 경우 시간대만으로 실제 출근 이동을 확정할 수 없다.

출근 시간대에는 다음 이동도 포함될 수 있다.

```text
등교
병원 방문
쇼핑
개인 업무
기타 생활 이동
```

따라서 청년 이동데이터는 전체연령 출근 목적 OD를 대체하는 메인 데이터로 바로 사용하지 않는다.

이 데이터는 이후 다음 용도로 활용한다.

- 청년층의 출근 시간대 이동 패턴 확인
- 전체연령 출근 OD와 목적지 구조 비교
- 전체연령 통근구조가 청년층에도 적용 가능한지 검증

### 산출물

이 노트북은 최종 분석 데이터 생성보다 원자료의 구조와 품질을 확인하고, 이후 청년 이동데이터의 필터링 및 집계 기준을 결정하는 데 목적이 있다.

## `04_build_commute_od.ipynb`

### 목적

월별 전체연령 이동데이터를 통합하고, 출근 목적 및 출근 시간 조건에 맞는 이동만 남겨 통근 OD 집계를 위한 전처리 데이터를 생성한다.

### 사용 데이터

- 전체연령 이동데이터
- 월별 출근 목적 이동 파일
- 출발 행정동, 도착 행정동, 이동목적, 출발시간, 도착시간, 이동량, 이동시간, 이동거리 포함

### 주요 전처리

1. 월별 데이터 파일 목록을 불러온다.
2. 각 파일의 컬럼 구성이 동일한지 확인한다.
3. 분석에 필요한 컬럼만 선택한다.
4. 행정동 코드는 문자열로 변환한다.
5. 출발시간과 도착시간의 자료형 및 표현 형식을 확인한다.
6. 이동량, 이동시간, 이동거리를 수치형으로 변환한다.
7. 핵심 컬럼의 결측치를 확인한다.
8. 이동량이 0 이하인 행을 확인한다.
9. 이동시간 또는 이동거리가 음수인 행을 확인한다.
10. 월별 파일을 하나의 데이터로 통합한다.
11. 이동목적 코드가 출근인 행만 유지한다.
12. 출발시간 또는 도착시간이 오전 07:00~09:40에 해당하는 행만 유지한다.

필터 조건은 다음과 같다.

```text
출발시간이 07:00~09:40
또는
도착시간이 07:00~09:40
```

13. 필터링 전후 행 수와 제거 비율을 확인한다.
14. 필터링 후 출발시간과 도착시간 분포를 다시 점검한다.
15. 필터링 완료 데이터를 별도 CSV로 저장한다.

### 주요 의사결정

출발시간과 도착시간이 모두 범위에 포함되어야 하는 조건이 아니라, 둘 중 하나만 포함되어도 유지하는 조건을 사용했다.

예를 들어 다음 이동은 실제 출근일 수 있다.

```text
06:40 출발 → 07:40 도착
09:20 출발 → 10:00 도착
```

두 시간이 모두 출근 시간 범위에 있어야 한다고 제한하면 조기 출발자, 장거리 통근자, 늦은 도착자가 과도하게 제거될 수 있다.

따라서 출발 또는 도착 중 하나가 출근 시간대에 해당하면 유지했다.

### 실행 결과 해석

필터링 결과에는 07:00 이전 출발시간이나 09:40 이후 도착시간이 일부 포함될 수 있다.

이는 전처리 오류가 아니라 `출발시간 또는 도착시간` 조건을 적용한 결과다.

필터링된 데이터는 약 1억 행, 약 11GB 규모로 이후 분석에 그대로 사용하기에는 크기 때문에 다음 노트북에서 OD 단위로 집계한다.

### 산출물

```text
all_age_commute_morning_0700_0940.csv
```

## `05_aggregate_all_age_commute_od.ipynb`

### 목적

행 단위로 저장된 대용량 출근 데이터를 거주동과 근무동의 조합으로 집계하여 분석 가능한 OD 테이블을 생성한다.

### 사용 데이터

```text
all_age_commute_morning_0700_0940.csv
```

### 주요 전처리 및 집계

1. 대용량 CSV 전체를 한 번에 메모리에 올리지 않고 청크 단위로 읽는다.
2. 분석에 필요한 컬럼만 선택하여 메모리 사용량을 줄인다.
3. 각 청크에서 행정동 코드를 문자열로 변환한다.
4. 이동량, 이동시간, 이동거리를 수치형으로 변환한다.
5. 집계에 필요한 핵심 값이 결측인 행을 확인하고 처리한다.
6. 출발 행정동은 `거주동`, 도착 행정동은 `근무동`으로 해석한다.
7. 각 행에 다음 가중합 변수를 생성한다.

```text
이동시간 가중합 = 이동시간 × 이동량
이동거리 가중합 = 이동거리 × 이동량
```

8. 각 청크에서 다음 기준으로 그룹화한다.

```text
거주동 코드 + 근무동 코드
```

9. OD별로 다음 값을 합산한다.

```text
출근 이동량 합계
이동시간 가중합
이동거리 가중합
```

10. 모든 청크의 중간 집계 결과를 다시 합쳐 최종 OD별로 재집계한다.
11. 다음 산식으로 OD별 평균 이동시간과 평균 이동거리를 계산한다.

```text
평균 이동시간
= 이동시간 가중합 / 출근 이동량

평균 이동거리
= 이동거리 가중합 / 출근 이동량
```

12. 계산에 사용한 중간 가중합 컬럼은 최종 결과에서 제거한다.
13. 거주동과 근무동 코드의 자료형을 다시 확인한다.
14. OD 중복 여부와 비정상 값을 검증한다.
15. 거주동 코드와 근무동 코드가 같은 내부 통근 OD의 규모를 확인한다.
16. 최종 OD 집계 파일을 저장한다.

### 검증

다음 항목을 확인했다.

- 최종 거주동-근무동 조합 중복 여부
- 거주동 및 근무동 개수
- 출근 이동량 합계
- 이동량이 0 이하인 OD
- 평균 이동시간이 음수인 OD
- 평균 이동거리가 음수인 OD
- 동일 행정동 내부 통근 OD의 수와 이동량 비중
- 저장 전후 행 수 및 컬럼 구조

실행 결과에서 최종 중복 OD와 음수 시간·거리 등 비정상 값은 확인되지 않았다.

### 주요 의사결정

OD별 이동시간과 이동거리는 단순 평균이 아니라 출근 이동량 가중평균으로 계산했다.

이동량이 큰 관측치와 작은 관측치를 동일하게 평균하면 실제 통근 흐름이 왜곡될 수 있기 때문이다.

동일 행정동 내부 이동도 제거하지 않았다.

같은 행정동 안에서 이루어지는 출근도 실제 통근이며, 이를 제거하면 근거리 통근이 많은 지역의 평균 통근시간이 인위적으로 높아질 수 있다.

### 실행 결과 해석

약 1억 건의 행 단위 이동데이터가 약 16만 개의 고유 OD로 축약되었다.

원본 이동 행은 줄었지만 다음 정보는 OD별로 보존된다.

- 총 출근 이동량
- 이동량을 반영한 평균 이동시간
- 이동량을 반영한 평균 이동거리

따라서 이후 경로 분석과 통근부담 산출에서는 대용량 원본이 아니라 이 OD 집계 데이터를 사용한다.

## `06_select_major_commute_destinations.ipynb`

### 목적

모든 거주동-근무동 조합을 사용하지 않고, 거주동별 출근량의 대부분을 설명하는 주요 근무동을 선정한다.

이를 통해 후속 경로 API 호출량을 줄이고, 대표적인 통근 흐름을 중심으로 통근시간과 교통비를 계산한다.

### 사용 데이터

```text
all_age_commute_od_aggregated.csv
```

### 주요 전처리 및 계산

1. OD 집계 파일을 불러온다.
2. 거주동 및 근무동 코드를 문자열로 변환한다.
3. 출근 이동량과 평균 이동시간을 수치형으로 변환한다.
4. 핵심 컬럼의 결측치 및 중복 OD를 확인한다.
5. 거주동별 전체 출근 이동량을 계산한다.
6. 각 OD의 목적지 비중을 계산한다.

```text
목적지 비중
= 해당 거주동-근무동 출근 이동량
  / 해당 거주동 전체 출근 이동량
```

7. 거주동별로 근무동을 출근 이동량이 큰 순서대로 정렬한다.
8. 정렬된 목적지 비중의 누적합을 계산한다.
9. 다음 세 가지 누적 출근량 기준을 각각 적용한다.

```text
70%
80%
90%
```

10. 누적 비중이 기준에 도달할 때까지의 목적지를 남긴다.
11. 기준을 처음 초과하게 만드는 마지막 목적지도 포함하여 실제 포함 비중이 기준 미만으로 내려가지 않도록 한다.
12. 기준별로 선택된 OD 수와 거주동별 목적지 수를 계산한다.
13. 선택된 목적지 범위 안에서 출근 이동량 비중을 다시 정규화한다.

```text
최종 가중치
= 선택된 OD 출근 이동량
  / 선택된 목적지의 출근 이동량 합계
```

14. 거주동별 최종 가중치 합계가 1인지 검증한다.
15. 최종 가중치를 이용해 기준별 대표 이동시간을 계산한다.
16. 70%, 80%, 90% 사이의 OD 수 및 대표시간 변화를 비교한다.
17. 각 기준 결과와 비교 요약표를 CSV로 저장한다.

### 기준 비교 결과

| 누적 기준 | 선택 OD 수 | 거주동당 평균 목적지 수 | 평균 포함 출근비중 |
|---|---:|---:|---:|
| 70% | 20,112 | 46.99 | 70.28% |
| 80% | 30,839 | 72.05 | 80.15% |
| 90% | 51,328 | 119.93 | 90.07% |

### 주요 의사결정

최종 분석 기준은 누적 출근량 80%로 선택했다.

70% 기준은 목적지 수를 가장 많이 줄일 수 있지만, 전체 출근량의 약 30%가 제외되어 비주류 및 장거리 통근 흐름을 충분히 반영하지 못할 수 있다.

90% 기준은 출근량을 더 많이 보존하지만, 거주동당 평균 목적지 수가 약 120개까지 증가하여 주요 목적지 선정 효과가 약해진다.

80%에서 90%로 높일 경우 약 2만 개 이상의 OD를 추가해야 하지만 대표 이동시간 변화는 평균적으로 크지 않았다.

따라서 80%는 다음 두 조건 사이의 절충 기준으로 사용한다.

```text
주요 출근 흐름 보존
+
후속 API 호출 및 계산량 축소
```

70%와 90% 결과는 제거하지 않고, 기준 변화에 따라 결과가 크게 달라지는지 확인하는 민감도 분석 자료로 사용한다.

### 해석 시 주의사항

이 노트북에서 계산한 대표 이동시간은 전체 출근자를 대상으로 한 원본 평균이 아니다.

선택된 주요 목적지의 출근 이동량을 다시 정규화하여 계산한 값이므로 다음과 같이 표현한다.

```text
주요 출근 목적지 기준 가중평균 이동시간
```

`전체 출근자의 평균 통근시간`으로 표현하지 않도록 주의한다.

## 07_prepare_api_targets.ipynb

## 08_geocode_and_test_route_apis.ipynb

- 구·신 행정동 코드표를 불러와 행정동별 자치구 정보를 결합한다.
- 동일한 행정동명이 여러 자치구에 존재할 수 있으므로 자치구와 행정동명을 함께 사용해 검색어를 만든다.
- 다음 형태로 주민센터 검색어를 구성한다.

> 서울특별시 + 자치구 + 행정동 + 주민센터

- 카카오 키워드 검색 API로 주민센터 후보를 조회한다.
- 검색 결과 중 행정복지센터 또는 주민센터 성격이 명확한 장소를 우선 선택한다.
- 검색된 주소가 목표 자치구와 일치하는지 확인한다.
- 행정동별 위도와 경도를 저장한다.
- 외부 통근 OD에 거주동과 근무동 주민센터 좌표를 각각 결합한다.
- 내부 통근은 TMAP 테스트 대상에서 제외한다.
- 외부 OD 한 건을 먼저 호출하여 TMAP 응답 구조를 확인한다.
- TMAP 응답에서 다음 정보를 추출한다.
  - 전체 소요시간
  - 전체 이동거리
  - 총 보행시간
  - 총 보행거리
  - 교통요금
  - 환승횟수
  - 버스·지하철 등 교통수단별 이용 구간
- 여러 TMAP 앱키를 순차적으로 사용하도록 호출 관리 로직을 구성한다.
- 기존 성공 결과가 있으면 다시 호출하지 않고 이어서 조회한다.
- 호출 성공 결과와 실패 결과를 분리하여 중간 저장한다.
- 오류가 발생하더라도 이미 수집한 결과가 사라지지 않도록 즉시 저장한다.

### 검증

다음 항목을 확인했다.

- 지오코딩 대상 행정동 수와 결과 행 수의 일치 여부
- 좌표가 수집되지 않은 행정동 수
- 행정동 코드 중복 여부

- 외부 OD에 거주동과 근무동 좌표가 모두 결합되었는지
- 내부 통근이 경로 API 호출 대상에서 제외되었는지
- TMAP 응답에서 시간, 거리, 요금 및 경로 구간이 정상적으로 추출되는지

- 성공 건수, 실패 건수 및 저장 파일 상태

### 주요 의사결정

행정동의 대표 좌표는 주민센터 좌표를 사용했다.

행정동 중심점이나 임의 좌표보다 주민센터는 실제 도로와 대중교통 접근이 가능한 위치이며, 모든 행정동에 비교적 일관된 기준으로 적용할 수 있기 때문이다.

주민센터 검색 시 행정동명만 사용하지 않고 자치구명을 함께 사용했다. 서울에는 동일하거나 유사한 행정동명이 존재할 수 있어 잘못된 자치구의 주민센터가 선택되는 것을 방지하기 위한 조치다.

경로 API는 먼저 소수 OD를 시험 호출하여 응답 구조와 수집 가능 변수를 확인한 뒤 전체 호출로 확장했다.

API 호출 과정에서 성공 결과를 누적 저장하여 호출 제한이나 일시적인 오류가 발생해도 이전 결과를 유지하도록 했다.

- TMAP 경로 조회 실패 결과 파일

## 11_build_commute_burden_metrics_no_confidence.ipynb

### 목적

10번에서 생성한 OD 단위 경로 데이터를 거주 행정동 단위로 집계하여 대표 통근시간, 통근거리, 교통비 및 통근시간 기회비용을 계산한다.

### 사용 데이터

- `commute_routes_analysis_ready.csv`

### 주요 전처리 및 계산

- OD 식별키 중복 여부와 필수 변수 존재 여부를 확인한다.
- 거주동별 최종 가중치 합이 1인지 검증한다.
- 내부 통근을 포함한 모든 선택 OD를 이용해 대표 편도 통근시간과 거리를 계산한다.

> 대표 편도 통근시간  
> = Σ(OD별 편도시간 × 최종 가중치)

> 대표 편도 통근거리  
> = Σ(OD별 편도거리 × 최종 가중치)

- 내부 통근은 요금이 결측이므로 요금이 존재하는 OD만 대상으로 가중치를 다시 정규화한다.

> 요금 재조정 가중치  
> = 해당 OD의 최종 가중치  
> / 해당 거주동에서 요금이 존재하는 OD의 가중치 합

- 재조정된 가중치로 대표 편도 교통비를 계산한다.
- 선택된 OD 가운데 시간과 거리가 존재하는 이동량 비율을 경로 포함률로 계산한다.
- 요금이 존재하는 이동량 비율을 교통비 산출 포함률로 계산한다.
- 거주동별 내부 통근 이동량과 내부 통근 비중을 계산한다.
- 출근 이동량이 큰 상위 목적지를 문자열로 정리한다.
- 주요 목적지가 전체 출근 이동량에서 차지하는 누적 비중을 계산한다.
- 값이 존재하는 OD를 이용해 대표 도보시간과 대표 환승횟수를 계산한다.
- 편도 통근값을 월 단위로 환산한다.

> 월 통근시간  
> = 대표 편도 통근시간 × 2 × 월평균 출근일수

> 월 통근교통비  
> = 대표 편도 교통비 × 2 × 월평균 출근일수

- 월 통근시간에 시간가치를 적용해 기회비용을 계산한다.

> 월 통근시간 기회비용  
> = 월 통근시간 × 시간당 시간가치

### 분석 기준

- 월평균 출근일수: 21일
- 시간가치: 시간당 10,320원

월 출근일수 21일은 법적으로 고정된 값이 아니라 분석을 위한 공통 가정이다.

공휴일과 연차 등 실제 비근무일을 고려하고 통근부담이 과대 추정되는 것을 방지하기 위해 22일보다 보수적인 21일을 적용했다.

지역 간 비교에서는 모든 행정동에 동일한 시간가치를 적용했다. 행정동별 임금을 다르게 적용하면 통근시간 차이뿐 아니라 직업과 임금구성 차이까지 지표에 함께 포함될 수 있기 때문이다.

### 검증

다음 항목을 확인했다.

- OD 식별키 중복 여부
- 시간·거리 결측 여부

### 주요 의사결정

통근시간과 거리는 내부 통근을 포함한 전체 선택 OD를 기준으로 계산했다.

교통비는 내부 통근 요금을 알 수 없으므로 요금이 확인된 OD 안에서 가중치를 다시 정규화해 추정했다.

따라서 대표 교통비는 모든 OD의 완전한 평균이 아니라 요금이 확인된 OD를 이용한 추정값이며, 해석 시 교통비 산출 포함률을 함께 확인해야 한다.

통근시간 기회비용은 실제 현금 지출이 아니라 통근에 사용한 시간의 비현금성 비용이다. 교통비와 기회비용은 의미가 다르므로 별도 변수로 유지했다.

## 12_build_louvain_commute_communities.ipynb

### 목적

전체연령 출근 OD를 행정동 간 네트워크로 구성하고 루바인 알고리즘을 적용하여 실제 출근 흐름을 기반으로 한 통근권을 도출한다.

또한 거주동별 목적지 집중도, 통근권 내부 이동 비율, 출근 유입·유출량 등 통근구조 지표를 계산하고 11번 통근부담 결과와 결합한다.

### 사용 데이터

- `all_age_commute_od_aggregated.csv`
- `commute_burden_by_home_dong.csv`

루바인 통근권 산출에는 누적 80%로 줄인 OD가 아니라 전체 출근 OD를 사용한다.

### 네트워크 구성

- 행정동을 노드로 사용한다.
- 행정동 사이의 출근 이동을 간선으로 사용한다.
- 출근 이동량을 간선 가중치로 사용한다.
- A→B와 B→A 이동량을 합쳐 무방향 간선으로 변환한다.
- 동일 행정동 내부 통근은 자기 루프이므로 루바인 커뮤니티 탐지 간선에서는 제외한다.
- 내부 통근은 거주동별 내부 통근 비중 계산에는 그대로 사용한다.

### 주요 전처리 및 계산

- 전체 출근 OD의 코드, 이동량 및 중복 여부를 확인한다.
- 양방향 OD를 하나의 무방향 가중 간선으로 합친다.
- 극소량 간선 제거 기준을 여러 분위수로 시험한다.
- 각 후보 기준에서 다음 값을 계산한다.
  - 남은 간선 수
  - 남은 행정동 수
  - 출근 이동량 보존율
  - 노드 보존율
- 전체 출근 이동량 95% 이상과 전체 행정동 99% 이상을 보존하는 후보 중 가장 강한 필터를 선택한다.
- 고정된 난수 시드로 루바인 커뮤니티 탐지를 수행한다.
- 큰 커뮤니티부터 순서대로 통근권 코드를 부여한다.
- 필터링으로 고립된 행정동이 존재하면 개별 통근권으로 보완한다.
- 루바인 결과의 모듈러리티를 계산한다.
- 거주동별 전체 목적지 비중을 이용해 다음 지표를 계산한다.
  - 목적지 HHI
  - 목적지 엔트로피
  - 정규화 엔트로피
  - 유효 목적지 수
- 각 OD에 거주동과 근무동의 통근권 코드를 결합한다.
- 거주동별 동일 통근권 내부 출근 비율과 외부 통근권 이동 비율을 계산한다.
- 출근자가 가장 많이 향하는 주요 목적지 통근권과 그 비중을 계산한다.
- 행정동별 출근 유입량, 출근 유출량, 순유입량과 유입·유출 비율을 계산한다.
- 통근권 안에서 출근 유입량이 가장 큰 행정동을 대표 업무 중심지로 선정한다.
- 11번 결과를 이용해 통근권별 대표 통근시간, 거리, 교통비와 기회비용을 가중평균한다.
- 거주동별 네트워크 지표와 11번 통근부담 결과를 결합한다.

### 지표 해석

#### 목적지 HHI

> 목적지 HHI  
> = Σ(목적지별 출근 비중²)

1에 가까울수록 출근 목적지가 소수 지역에 집중되어 있음을 의미한다.

#### 목적지 엔트로피

출근 목적지가 여러 지역에 고르게 분산될수록 값이 커진다.

HHI와 엔트로피는 반대 방향으로 해석한다.

- HHI가 높음: 특정 목적지 집중
- 엔트로피가 높음: 목적지 다양성 증가

#### 동일 통근권 내부 출근 비율

> 동일 통근권 내부 출근 비율  
> = 같은 통근권으로 이동한 출근량  
> / 해당 거주동 전체 출근량

값이 높을수록 출근 흐름이 해당 통근권 안에서 이루어지는 비중이 크다는 뜻이다.

#### 출근 유입·유출 비율

> 출근 유입·유출 비율  
> = 출근 유입량 / 출근 유출량

1보다 크면 출근자가 빠져나가는 양보다 들어오는 양이 많은 업무형 지역 패턴을 나타낸다.

### 검증

다음 항목을 확인했다.

- 전체 OD의 중복 및 이동량 이상 여부
- 간선 필터별 이동량 보존율
- 간선 필터별 행정동 보존율
- 모든 행정동의 통근권 코드 부여 여부
- 통근권 코드 결측 여부
- 동일 통근권 내부 비율과 외부 통근권 비율의 합이 1인지
- 목적지 비중 합이 거주동별로 1인지
- HHI와 엔트로피의 값 범위
- 내부 통근 비중의 값 범위
- 출근 유입·유출량 결측 여부
- 11번 통근부담 결과와 네트워크 지표의 병합 여부
- 최종 결과의 거주동 코드 중복 여부

### 주요 의사결정

루바인 커뮤니티 탐지는 방향을 제거한 무방향 네트워크에서 수행했다.

출근 OD는 방향성이 있지만, 통근권 탐지의 목적은 행정동 사이의 강한 상호 연결 구조를 찾는 것이므로 양방향 이동량을 합산했다.

다만 거주동별 유출량, 근무동별 유입량, 동일 통근권 내부 출근 비율 등은 이동 방향이 중요한 지표이므로 원래 방향이 유지된 OD를 사용했다.

극소량 간선 제거 기준은 하나의 임의값으로 정하지 않고 이동량과 행정동 보존율을 기준으로 선택했다.

루바인 결과를 반복 실행해도 동일하게 재현할 수 있도록 난수 시드를 고정했다.

### 해석 시 주의사항

- 루바인 통근권은 기존 행정구역을 대체하는 기준이 아니다.
- 통근권은 전체연령 출근 OD의 연결구조를 설명하는 보조 분석이다.
- 동일 통근권 내부 출근 비율이 높다고 해서 실제 통근시간이 반드시 짧은 것은 아니다.
- 대표 업무 중심지는 출근 유입량 기준으로 선정한 결과다.
- 업무 중심지 해석에는 사업체, 종사자 및 생활인구 자료를 함께 검토할 필요가 있다.
- 루바인 통근권은 청년만의 통근권이 아니라 전체연령 출근 흐름을 기반으로 한다.

## `13_build_destination_concentration_metrics.ipynb`

### 목적

전체 출근 OD 데이터를 이용하여 거주 행정동별로 출근 목적지가 특정 지역에 얼마나 집중되어 있는지를 계산한다.

목적지 집중도는 루바인 통근권과 별개의 지표이며, 각 거주동에서 출발한 출근 이동이 여러 근무동에 분산되어 있는지 또는 일부 근무동에 집중되어 있는지를 나타낸다.

### 사용 데이터

* `all_age_commute_od_aggregated.csv`
* 전체연령 출근 OD 집계 데이터

목적지 집중도 계산에는 누적 출근량 80%로 선정한 주요 OD가 아니라 전체 출근 OD를 사용한다.

### 주요 전처리 및 계산

1. 전체 출근 OD 데이터를 불러온다.
2. 거주동 코드와 근무동 코드를 문자열로 정리한다.
3. 출근 이동량을 수치형으로 변환한다.
4. OD 중복 및 이동량 결측·이상값을 확인한다.
5. 거주동별 전체 출근 이동량을 계산한다.
6. 각 근무동으로 향하는 출근량이 거주동 전체 출근량에서 차지하는 비중을 계산한다.

```text
목적지별 출근 비중
= 해당 거주동-근무동 출근 이동량
  / 해당 거주동 전체 출근 이동량
```

7. 거주동별 목적지 비중을 이용해 다음 지표를 계산한다.

* 목적지 HHI
* 최대 목적지 비중
* 상위 3개 목적지 비중
* 목적지 엔트로피
* 목적지 정규화 엔트로피
* 유효 목적지 수
* 전체 목적지 수
* 주요 출근 목적지

### 주요 지표

#### 목적지 HHI

```text
목적지 HHI
= Σ(목적지별 출근 비중²)
```

값이 1에 가까울수록 출근이 소수 목적지에 집중되어 있음을 의미한다.

여러 목적지에 고르게 분산될수록 값이 작아진다.

#### 목적지 엔트로피

목적지별 출근 비중이 여러 지역에 고르게 분산될수록 값이 커진다.

HHI와는 반대 방향으로 해석한다.

```text
HHI 높음
→ 특정 목적지 집중

엔트로피 높음
→ 여러 목적지로 분산
```

#### 목적지 정규화 엔트로피

목적지 수가 다른 행정동끼리 비교할 수 있도록 엔트로피를 0~1 범위로 정규화한 값이다.

최종 행정동 유형화에서는 목적지 수 자체의 영향을 줄이기 위해 목적지 집중구조를 나타내는 주요 변수로 활용한다.

### 검증

다음 항목을 확인했다.

* 거주동별 목적지 비중 합이 1인지
* 목적지 HHI의 값 범위
* 정규화 엔트로피의 값 범위
* 출근 이동량이 0 이하인 OD 존재 여부
* 거주동별 결과 중복 여부
* 목적지 수와 주요 목적지 정보의 정상 생성 여부

12번 노트북에서도 목적지 HHI가 계산되어 있는 경우 동일한 전체 OD를 사용했으므로 두 결과를 교차 비교한다.

이 검증은 루바인 결과를 목적지 집중도 계산에 사용하는 것이 아니라, 독립적으로 다시 계산한 결과가 기존 결과와 일치하는지 확인하기 위한 품질검사다.

### 주요 의사결정

목적지 집중도는 누적 출근량 80% OD가 아니라 전체 출근 OD를 기준으로 계산했다.

80% 자료만 사용하면 출근량이 작은 목적지가 제거되어 목적지가 실제보다 적게 보이고 HHI가 과도하게 높아질 수 있기 때문이다.

최종 군집분석에서는 HHI뿐 아니라 목적지 정규화 엔트로피를 함께 검토한다.

HHI와 엔트로피는 유사한 정보를 반대 방향으로 표현하기 때문에 최종 변수 선정 과정에서 중복 여부를 확인한다.

### 해석 시 주의사항

* 목적지 집중도는 목적지가 어디인지를 나타내는 지표가 아니라 목적지 분포가 얼마나 집중되어 있는지를 나타낸다.
* HHI가 높다고 통근시간이나 교통비가 반드시 높은 것은 아니다.
* 목적지 수가 적은 지역은 구조적으로 HHI가 높아질 수 있으므로 목적지 수, 최대 목적지 비중 및 유효 목적지 수를 함께 확인한다.
* 전체연령 출근 OD를 사용하므로 청년층만의 출근 목적지 구조로 해석하지 않는다.
* 루바인 통근권과 독립적으로 계산한 통근구조 지표이며 이후 행정동 유형화의 입력 변수로 활용한다.

### 산출물

```text
commute_destination_shares_by_home_dong.csv
commute_destination_concentration_by_home_dong.csv
```

첫 번째 파일은 거주동-근무동별 목적지 비중을 보존한 상세 데이터이며, 두 번째 파일은 행정동 한 개당 한 행으로 집계한 목적지 집중도 결과다.

## `14_compare_dong_clustering_methods_final.ipynb`

### 목적

서울시 행정동을 주거비, 통근부담 및 통근구조가 서로 다른 유형으로 구분하기 위해 다양한 군집분석 방법을 비교하고 최종 유형화 방법과 적절한 군집 수를 검토한다.

단순히 Silhouette Score가 가장 높은 군집을 선택하는 것이 아니라 다음을 함께 고려한다.

* 유형 간 실제 프로파일 차이
* 군집 크기 균형
* 반복표본 안정성
* 알고리즘 간 결과 합의도
* 표면주거비 결측 보완에 대한 민감도
* 서비스에서의 설명 가능성

최종 후보 군집 수는 4~8개로 제한하며 3개 군집은 최종 후보에서 제외한다.

### 사용 데이터

주요 입력 데이터는 다음 분석 결과를 결합하여 사용한다.

* 행정동별 표면주거비
* `commute_burden_by_home_dong.csv`
* `commute_dong_network_metrics.csv`
* `commute_destination_concentration_by_home_dong.csv`
* 청년 1인세대 비중 데이터

### 표면주거비 집계

한 행정동에 단독·다가구, 연립·다세대, 오피스텔 등 여러 주택유형이 존재하므로 주택유형별 중앙값을 그대로 하나의 행정동 값으로 사용할 수 없다.

행정동별 대표 표면주거비는 다음 방식으로 계산한다.

```text
행정동 표면주거비
= 주택유형별 중앙값의 표본수 가중평균
```

각 주택유형의 거래 표본수를 가중치로 사용한다.

원자료가 주택유형별 중앙값만 제공하기 때문에 전체 개별 거래를 이용한 정확한 통합 중앙값을 재계산할 수 없다는 점을 함께 명시한다.

### 표면주거비 결측 처리

비아파트 전월세 거래가 존재하지 않아 표면주거비를 산출하지 못한 행정동은 유사 행정동 기반으로 값을 보완한다.

1. 표면주거비가 존재하는 행정동을 donor 후보로 설정한다.
2. 다음 변수들을 RobustScaler로 표준화한다.

```text
대표 편도통근시간
월 통근교통비
동일통근권 내부출근비율
목적지 정규화엔트로피
```

3. 같은 자치구 안에서 통근 특성이 가장 가까운 5개 donor를 찾는다.
4. 해당 5개 행정동의 표면주거비 중앙값을 결측값으로 사용한다.
5. 어떤 행정동을 donor로 사용했는지 별도 감사 테이블에 저장한다.
6. 같은 자치구에 donor가 부족하면 동일 권역, 이후 서울 전체 순으로 탐색 범위를 넓힌다.

통근 관련 다른 변수의 소수 결측은 같은 자치구 중앙값으로 보완하고, 자치구 전체가 결측인 경우 서울 전체 중앙값을 사용한다.

### 유형화 변수 설계

최종 유형화에는 크게 두 개의 블록을 사용한다.

#### 부담 블록

```text
표면주거비
대표 편도 통근시간
월 통근교통비
```

#### 통근구조 블록

```text
동일 통근권 내부 출근 비율
목적지 정규화 엔트로피
```

목적지 HHI는 엔트로피와 정보가 중복될 가능성이 있기 때문에 기본 5개 변수에는 포함하지 않고 보조 6변수 모델에서 비교한다.

청년 1인세대 비율은 군집 생성 변수에서 제외하고 최종 유형이 결정된 뒤 사후적으로 해석한다.

### 군집화 가능성 점검

본격적인 군집분석 전에 데이터 자체에 군집 구조가 존재하는지 확인한다.

* Hopkins statistic
* PCA 누적 설명력

Hopkins statistic이 0.5에 가까우면 무작위적인 구조에 가깝고, 1에 가까울수록 군집화 가능한 구조가 있다는 의미로 해석한다.

다만 행정동 유형화는 자연적으로 완전히 분리된 집단을 찾는 것이 아니라 서비스에서 비교 가능한 상대적 유형을 만드는 목적도 있으므로 자연군집이 매우 강하지 않다고 분석을 중단하지 않는다.

### 데이터 표현 방식 비교

알고리즘뿐 아니라 변수의 표현 방법도 함께 비교한다.

```text
RAW_STANDARD
RAW_ROBUST
BLOCK_BALANCED
PCA_90
```

`BLOCK_BALANCED`에서는 부담 변수 3개와 통근구조 변수 2개의 개수 차이 때문에 부담 블록이 자동으로 더 큰 영향을 받지 않도록 다음과 같이 비중을 맞춘다.

```text
부담 블록 50%
통근구조 블록 50%
```

* MiniBatchKMeans
* BisectingKMeans
* KMedoids
* Agglomerative Ward
* Agglomerative Complete
* Agglomerative Average
* Gaussian Mixture
* Spectral Clustering
* Birch

고정된 군집 수를 사전에 설정하지 않는 방법도 별도로 비교한다.

* DBSCAN
* OPTICS
* HDBSCAN
* MeanShift
* AffinityPropagation

경계가 명확하지 않은 행정동을 고려하기 위해 Fuzzy C-Means도 추가 비교한다.

### 후보 필터 기준

최종 후보는 다음 조건을 우선 적용한다.

```text
군집 수: 4~8개
최소 군집 크기: 30개 행정동 이상
최대 군집 크기: 전체의 38% 이하
노이즈 비율: 10% 이하
```

조건을 충족하는 후보가 지나치게 적을 경우에만 보조적으로 다음 수준까지 완화한다.

```text
최소 군집 크기: 20개
최대 군집 크기: 45%
```

단순히 전체 평가점수 상위 모델만 남기지 않고 변수조합과 군집 수별 우수 모델을 균등하게 남겨 특정 알고리즘이나 특정 k가 후보를 독식하지 않도록 한다.

### 반복표본 안정성

같은 분석을 데이터 일부를 반복 추출하여 다시 수행했을 때 유사한 유형이 만들어지는지 확인한다.

변수표현과 군집 수별로 우수 후보를 남긴 뒤 반복표본 군집 결과와 원래 군집 결과의 일치 정도를 평가한다.

단일 데이터에서만 잘 분리되는 결과보다 표본이 조금 변해도 비슷한 구조가 유지되는 결과를 우선한다.

### 알고리즘 간 합의도

같은 변수표현과 같은 군집 수에서 서로 다른 알고리즘이 유사한 행정동 구조를 발견하는지 비교한다.

특정 알고리즘 하나에서만 좋은 결과가 나온 모델보다 여러 알고리즘에서 반복적으로 나타나는 구조를 더 신뢰한다.

### 표면주거비 결측 보완 민감도

표면주거비가 보완된 일부 행정동 때문에 전체 유형 구조가 만들어진 것은 아닌지 확인한다.

다음을 각각 유형화한 뒤 공통 행정동의 군집 결과를 ARI로 비교한다.

```text
전체 427개 행정동
vs
표면주거비 원자료가 존재하는 행정동
```

### 최종 후보 종합평가

종합점수는 다음 항목을 반영한다.

```text
프로파일 분리도           25%
군집 크기 균형           25%
반복표본 안정성          20%
내부 군집품질            15%
알고리즘 합의도          10%
표면주거비 대체 민감도     5%
```

Silhouette Score 하나만으로 최종 모델을 결정하지 않는다.

군집 수 자체에는 가산점이나 감점을 주지 않는다.

### k=4~8 프로파일 비교

각 군집 수별 최고 후보를 별도로 비교한다.

```text
k=4
k=5
k=6
k=7
k=8
```

유형 수가 하나 늘어났을 때 기존 유형이 단순히 둘로 나뉘는지, 실제로 새로운 주거·통근 구조가 발견되는지를 확인한다.

새로운 특성이 명확하지 않고 기존 유형을 세분화하는 데 그칠 경우 과도한 군집 수로 판단한다.

### 4사분면 기준형

군집분석 결과와 별도로 사용자가 직관적으로 이해할 수 있는 두 종류의 4사분면 분류를 생성한다.

#### 표면주거비 × 통근부담

통근부담은 다음 지표의 표준점수를 결합한다.

```text
통근시간
+
교통비
```

이를 이용해 주거비 수준과 통근부담 수준을 동시에 비교한다.

#### 종합부담 × 통근구조

종합부담은 다음 지표를 결합한다.

```text
주거비
+
통근시간
+
교통비
```

통근구조는 다음 방향으로 점수화한다.

```text
동일 통근권 내부출근비율 높음
+
목적지 집중도 높음
```

4사분면은 군집분석의 정답으로 사용하지 않고 사용자의 현재 부담구조를 빠르게 설명하는 상위 설명 레이어로 활용한다.

### 2단계 계층형 유형화 비교

5개 변수를 한 번에 군집화하는 방식 외에 다음 구조도 별도로 비교한다.

#### 1단계

통근구조 변수로 큰 갈래를 나눈다.

```text
동일 통근권 내부출근비율
목적지 엔트로피
```

#### 2단계

각 통근구조 그룹 안에서 부담 변수로 다시 세분화한다.

```text
표면주거비
통근시간
교통비
```

최종 유형 수가 4~8개이고 최소 하위유형이 20개 이상인 결과만 후보로 남긴다.

### 주요 의사결정

최종 유형화에서는 다음 원칙을 적용한다.

* 3개 유형은 최종 후보에서 제외한다.
* 주거비와 통근부담만으로 유형화하지 않고 통근구조 변수를 반드시 포함한다.
* 청년 1인세대 비율은 군집 생성에 사용하지 않는다.
* Silhouette Score가 가장 높은 모델을 자동으로 선택하지 않는다.
* 지나치게 작은 군집은 서비스에서 하나의 유형으로 설명하기 어렵기 때문에 제외한다.
* 군집 수가 증가할 때 실제 새로운 유형이 나타나는지를 확인한다.
* 유형화는 추천 결과 자체가 아니라 서울의 주거·통근 구조를 요약하는 분석 레이어로 사용한다.

### 유형화 활용 구조

유형화 결과는 다음 목적으로 활용한다.

1. 현재 거주동의 주거·통근 구조 설명
2. 현재와 다른 특성을 가진 행정동 탐색
3. 서울 427개 행정동을 유형 단위로 먼저 압축하여 탐색
4. 같은 유형 또는 반대 특성의 후보 탐색
5. 15번 실제 근무지 기반 비교 결과를 설명하는 메타정보

최종 거주지 추천은 유형만으로 결정하지 않고 실제 근무지를 기준으로 통근시간, 교통비 및 총부담을 다시 계산한다.

최종 유형은 주거비, 통근시간, 교통비 및 통근구조 프로파일을 기준으로 다음과 같이 정의한다.

청년 1인세대 비율은 군집 생성 변수에서 제외한다.

최종 유형이 확정된 뒤 각 유형의 인구구성을 보조적으로 설명하기 위해 다음을 비교한다.

* 유형별 분포
* Kruskal-Wallis 검정

분석 목적은 다음과 같다.

```text
주거·통근 구조로 이미 형성된 6개 유형 사이에서
청년 1인세대 비율에도 차이가 나타나는가?
```

따라서 청년 1인세대 비율이 높다는 이유로 특정 유형이 만들어졌다고 해석하지 않는다.

### 대표 행정동 산출

각 유형의 군집 중심과 가장 가까운 행정동을 대표동으로 선정한다.

각 군집 내에서 거리 차이가 작은 상위 15%를 경계동으로 분류한다.

## `15_analyze_housing_commute_insights_final_v3.ipynb`

사용자의 예산·소득·선호가 바뀌면 추천 결과는 언제 바뀌는가?

* `dong_typology_final.csv`
* `commute_routes_analysis_ready.csv`
* `commute_burden_by_home_dong.csv`

### 공통 분석 기준

월평균 출근일수는 21일을 사용한다.

메인 분석의 시간가치는 특정 사용자의 소득을 가정하지 않고 모든 지역에 공통으로 다음 값을 사용한다.

```text
시간가치
= 시간당 10,320원
```

다음 산식으로 월 단위 통근부담을 계산한다.

```text
월 통근시간
= 편도 통근시간 × 2 × 21일

월 교통비
= 편도 교통비 × 2 × 21일

월 통근시간비용
= 월 통근시간 × 시간가치

총 주거·통근 부담
= 표면주거비
+ 월 교통비
+ 월 통근시간비용
```

소득 수준에 따른 시간가치 차이는 메인 결과에 적용하지 않고 별도의 민감도 분석에서만 사용한다.

### 내부 통근 교통비 처리

10번에서는 동일 행정동 내부 통근의 실제 교통수단을 확인할 수 없기 때문에 교통비를 임의로 0원으로 처리하지 않았다.

이는 내부 통근의 실제 요금을 관측한 값이 아니라 OD별 총부담 비교를 위한 proxy라는 점을 구분한다.

### 분석 1. 주거비를 줄이면 통근부담이 얼마나 늘어나는가

같은 근무동을 기준으로 현재보다 저렴한 거주지를 선택했을 때 통근부담이 얼마나 증가하는지를 분석한다.

#### 기준 거주지 설정

근무동별로 편도 통근시간이 30분 이내인 거주동들의 표면주거비 중앙값을 계산한다.

해당 중앙값과 실제 주거비가 가장 가까운 행정동을 기준 거주동으로 선정한다.

#### 주요 계산 지표

기준 거주동보다 주거비가 낮은 후보를 대상으로 다음 값을 계산한다.

* 주거비 절감액
* 편도 통근시간 증가
* 월 교통비 증가
* 월 통근시간비용 증가
* 실질 순절감액
* 손익분기 주거비 절감액

```text
실질 순절감액
= 주거비 절감액
- 추가 월 교통비
- 추가 월 통근시간비용
```

주거비가 낮아졌더라도 추가 통근비용이 절감액보다 크면 실질적으로는 비용이 증가할 수 있다.

#### 10만 원 절감당 지표

주거비 차이가 매우 작은 후보에 100,000원을 곱해 환산하면 비율이 비정상적으로 커질 수 있다.

따라서 10만 원 절감당 지표는 실제 주거비 절감액이 최소 10만 원 이상인 후보에서만 계산한다.

```text
10만 원 절감당
편도 통근시간 증가

10만 원 절감당
월 교통비 증가

10만 원 절감당
월 통근시간비용 증가
```

평균은 극단값의 영향을 받을 수 있기 때문에 중앙값을 핵심 해석값으로 우선 사용한다.

#### 보조분석

* 주거비와 통근시간 산점도
* 근무동별 단순 관계 회귀
* 주거비 10만 원 구간별 평균 통근시간

이 분석은 주거비가 낮아지면 통근시간이 반드시 늘어난다는 인과관계를 증명하는 것이 아니라 실제 데이터에서 나타나는 관계와 경향을 확인하는 용도로 사용한다.

### 분석 2. 어떤 지역이 실제로 비용 효율적인가

주거비가 낮은 지역과 주거·통근 총부담이 낮은 지역이 실제로 같은지 비교한다.

근무동별 주거비와 총부담의 중앙값을 기준으로 다음 네 유형을 만든다.

```text
A
저주거비 · 저총부담
→ 실질 비용 효율

B
저주거비 · 고총부담
→ 월세 착시

C
고주거비 · 저총부담
→ 숨은 효율

D
고주거비 · 고총부담
→ 종합 부담 큼
```

### 주거비 순위와 총부담 순위 비교

각 근무동 안에서 다음 두 순위를 계산한다.

```text
주거비가 낮은 순위

총 주거·통근 부담이 낮은 순위
```

두 순위의 차이를 이용해 주거비만 보았을 때보다 총부담 기준에서 평가가 좋아지는 지역과 나빠지는 지역을 확인한다.

두 순위 사이의 Spearman 순위상관계수도 계산하여 주거비만으로 지역을 선택했을 때 총부담 순위와 얼마나 유사한지 확인한다.

### 소득 시나리오 분석

시간의 가치를 사용자 소득에 따라 다르게 평가하는 경우도 별도로 비교한다.

대표 시나리오는 다음과 같다.

```text
저소득 청년
월소득 220만 원
시간가치계수 0.3

중간소득 청년
월소득 300만 원
시간가치계수 0.5

고소득 청년
월소득 400만 원
시간가치계수 0.7
```

소득과 시간가치계수가 높을수록 동일한 통근시간에 부여되는 시간비용이 커지기 때문에 총부담 기준의 거주지 순위가 달라질 수 있다.

### 분석 3. 근무지에 따라 최적 거주지가 어떻게 달라지는가

동일한 거주동도 실제 근무지가 어디인지에 따라 통근시간과 교통비가 달라지므로 근무지별 추천 순위 변화를 분석한다.

대표 업무지구를 구성하고 다음 조건으로 후보를 제한한다.

```text
표면주거비 80만 원 이하

편도 통근시간 60분 이하
```

여러 행정동으로 구성된 업무지구는 출근 이동량을 가중치로 사용하여 거주동별 통근시간, 교통비 및 총부담을 집계한다.

### 주요 분석

* 업무지구별 비용 효율 Top 10
* 업무지구별 추천 1순위
* 업무지구 간 Top 10 중복률
* 동일 거주동의 업무지구별 순위 변화
* 업무지구 특화도
* 권역 단위 비용 효율 요약

Top 10 중복률이 낮을수록 근무지에 따라 적합한 거주지가 크게 달라진다는 의미다.

### 데이터 해석 범위

현재 대중교통 경로 데이터는 거주동별 전체 목적지 중 출근량 누적 80%에 해당하는 주요 OD를 중심으로 수집했다.

따라서 업무지구 분석은 서울 427개 거주동 × 모든 근무동의 완전한 조합을 비교한 결과가 아니라 확보된 주요 통근 OD 범위에서 해석한다.

### 권역 단위 요약

동 단위 추천만 제시하면 서로 인접한 행정동이 Top 10을 대부분 차지할 수 있기 때문에 권역 정보가 존재하는 경우 다음 단계로 결과를 정리한다.

```text
권역 선택
→
권역 안의 세부 추천 행정동
```

### 분석 4. 추천 결과를 결정하는 핵심 조건은 무엇인가

거주 후보별 추천점수를 생성하고 사용자의 조건이 바뀌었을 때 추천 순위가 얼마나 달라지는지 분석한다.

비용형 변수는 모두 낮을수록 좋은 방향의 0~100 점수로 변환한다.

기본 추천점수는 다음 요소를 이용한다.

```text
주거비
통근시간
교통비
```

현재 프로젝트 데이터에 생활비나 주거환경 점수가 존재하지 않기 때문에 없는 변수를 임의로 생성하지 않는다.

### 기본 가중치

```text
주거비     40%
통근시간   30%
교통비     10%
```

실제 계산에서는 현재 존재하는 변수들의 가중치 합이 1이 되도록 다시 정규화한다.

### 가중치 민감도

사용자가 주거비를 더 중요하게 보거나 통근시간을 더 중요하게 볼 경우 추천 순위가 어떻게 변하는지 확인한다.

주거비 가중치를 변화시키고 나머지 통근시간과 교통비는 기존 3:1 비율을 유지한다.

근무동별 추천 1순위가 처음 변경되는 가중치를 전환점으로 기록한다.

### 소득 민감도

월소득이 달라졌을 때 시간가치도 변화하도록 계산하여 추천 순위 변화를 비교한다.

메인 분석에서는 공통 시간가치 10,320원을 사용하지만 이 분석에서만 사용자 소득 기반 시간가치를 적용한다.

근무동별 추천 1순위가 변경되는 소득 수준도 전환점으로 저장한다.

### 예산 민감도

사용자의 최대 주거비 예산을 변화시키면서 다음을 확인한다.

* 이용 가능한 후보 수
* 추천 1순위 변화
* 예산 10만 원 증가 시 새롭게 등장하는 후보
* 추가 예산이 추천 결과를 실제로 개선하는 정도

### 추천 안정성

사용자 조건을 조금 변경했을 때 추천 결과가 얼마나 안정적으로 유지되는지 다음 지표로 평가한다.

```text
Top 5 중복률

전체 순위 Spearman 상관계수

평균 절대 순위변동
```

조건이 조금 달라졌는데 이 값들이 크게 변하면 추천 결과가 사용자 조건에 민감하다는 의미다.

### 14_2 유형화 결과 활용

각 거주동에 다음 정보를 함께 결합한다.

* 최종 6개 행정동 유형
* 주거비 × 통근부담 4사분면
* 종합부담 × 통근구조 4사분면
* 청년 1인세대 비율

이 정보는 추천점수를 직접 높이거나 낮추지 않는다.

예를 들어 추천 후보가 선정된 뒤 다음과 같이 결과를 설명하는 용도로 사용한다.

```text
현재보다 주거비가 낮지만
장거리 통근 비중이 높은 유형

주거비는 상대적으로 높지만
직주근접성이 높은 유형
```

따라서 유형화와 개인화 추천의 역할을 분리한다.

```text
14_2
→ 서울 행정동의 구조적 특성을 설명

15
→ 사용자의 실제 근무지와 조건에 따라 후보를 비교
```

### 해석 시 주의사항

* 주거비와 통근시간 사이의 결과는 인과관계가 아니라 데이터에서 확인된 관계와 경향으로 표현한다.
* 총 주거·통근 부담은 시간가치를 어떻게 설정하는지에 따라 달라질 수 있으므로 절대적인 비용으로 해석하지 않는다.
* 내부 통근 교통비에 사용한 거주동 대표 교통비는 실제 내부 OD 요금이 아니라 보조 추정값이다.
* 소득, 예산 및 가중치 전환점은 실제 데이터에서 계산된 경우에만 결과 설명에 사용한다.
* 현재 데이터에 없는 생활비나 주거환경 수준을 임의로 추천점수에 추가하지 않는다.
* 업무지구 분석은 누적 출근량 80% 주요 OD 범위 안에서 수행된 결과다.
* 6개 행정동 유형과 4사분면은 추천을 직접 결정하는 변수가 아니라 추천 결과를 해석하는 메타정보다.
