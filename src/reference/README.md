# src/reference/ — 기준 데이터

## 이 폴더가 왜 따로 있나

행정동 코드는 이 프로젝트의 모든 데이터를 잇는 뼈대다. 실거래가·상권매출·생활이동·생활인구가 전부 행정동 단위인데, 문제는 **소스마다 코드 체계도 기준 시점도 다르다**는 것이었다.

- **코드 자릿수가 다르다** — KIKmix는 10자리, 상권분석·생활이동·생활인구는 8자리
- **이름 표기가 다르다** — 같은 동을 "창신제1동"과 "창신1동"으로 쓴다. 실제로 181건
- **기준 시점이 다르다** — 행정동 개편을 반영한 시점이 소스마다 제각각이라, 어떤 파일엔 있고 어떤 파일엔 없는 동이 생긴다

그래서 "무엇이 서울의 행정동인가"를 한 곳에서 정의하고, 나머지는 전부 그것을 참조하게 만들었다. 이 폴더가 그 한 곳이다.

## 왜 파일이 두 개인가 (중요)

처음에는 기준표를 만드는 스크립트 하나였다. 그런데 소스별 보유 현황까지 그 안에서 채우다 보니 **순환 의존**이 생겼다. 기준표를 만들려면 산출물을 읽어야 하는데, 산출물을 결합하려면 기준표가 있어야 한다. 파이프라인 맨 앞에서도 맨 뒤에서도 돌 수 없는 상태가 된 것이다.

그래서 성격이 다른 두 일을 분리했다.

```
build_region_master.py     KIKmix만 읽는다        → 파이프라인 최상단
        ↓ (기준표 생성)
   [전처리 · 지표 산출 · 분석]
        ↓ (산출물 생성)
check_region_coverage.py   산출물을 대조한다      → 파이프라인 최하단
```

## build_region_master.py — 무엇이 서울의 행정동인가

**하는 일**: 행정안전부 KIKmix에서 서울 현행 행정동 **427개**를 추출하고, 자치구를 5대 권역에 매핑하고, 폐지된 행정동을 현행 코드에 연결한 매핑표를 만든다.

**코드 결합 규칙**: 10자리 코드의 **앞 8자리가 8자리 통계청 코드와 같다.** 표면주거비 420개로 전수 검증했고 불일치는 0이었다. 그래서 결합은 무조건 코드로 한다. 이름 결합은 위에 적은 표기 차이 때문에 조용히 누락되므로 금지다.

**폐지 코드를 다루는 방식**: 매핑 근거는 추정이 아니라 KIKmix의 **생성일자**다. 신설동·용두동의 생성일자가 20250701이므로, 그 이전 체계의 용신동(11230536)이 이 둘로 분동된 것이다. 이런 식으로 9건을 확정했고 분동(1:N)도 표현한다.

```
용신동    → 신설동 + 용두동      1:N 분동   2025-07-01
상일동    → 상일제1동 + 상일제2동  1:N 분동   2021-07-01
일원2동   → 개포3동              1:1 개편   2022-12-23
강북구 6개 코드 재부여                        2019-01-01
```

**자체 검증**: 권역 매핑에 실패한 자치구가 있거나 8자리 코드에 중복이 생기면 즉시 중단한다. 앞 8자리를 결합축으로 쓰는 전제가 깨지는 상황이기 때문이다.

**입력 → 출력**: `대한민국_법정동_행정동_코드.xlsx` → `행정동_기준코드표.csv`(427행), `행정동_폐지코드_매핑.csv`(9행)

## check_region_coverage.py — 어느 소스에 어느 동이 있나

**하는 일**: 기준표를 놓고 각 산출물이 어느 행정동을 갖고 있는지 대조해 보유 플래그를 붙인다.

**핵심은 "비어 있음"을 두 종류로 가르는 것**이다. 버그로 빠진 것과 원래 없는 것은 다르게 다뤄야 한다.

- 표면주거비에 없는 7개(하계2동·상계8동·반포본동·잠실7동 등)는 전부 **대단지 아파트 지역**이다. 필터가 아파트를 제외하니 비아파트 임차 거래가 아예 없어서 빠진 것이지 누락이 아니다
- 기준표에 없는 코드가 나오면 **폐지코드 매핑으로 설명되는지 자동 대조**한다. 설명되면 넘어가고, 설명 안 되는 코드가 남으면 새 개편이 생겼거나 매핑이 낡았다는 신호다

**파일명을 패턴으로 찾는 이유**: 공공데이터는 받을 때마다 파일명이 달라진다. 정확한 이름을 하드코딩했다가 "파일 없음"으로 건너뛰어져 진단이 반쪽만 돌아간 적이 있었다. 지금은 glob 패턴과 코드 컬럼 후보를 순서대로 시도한다.

**입력 → 출력**: `행정동_기준코드표.csv` + 각 산출물 → `행정동_소스별_커버리지.csv`

## 한 줄 요약표

| 파일 | 실행 시점 | 한 줄 요약 |
|---|---|---|
| build_region_master.py | 맨 처음 | 서울 행정동 427개를 확정하고 폐지 코드를 현행에 연결한다 |
| check_region_coverage.py | 맨 마지막 | 소스별 보유 현황을 대조해 설명되는 결측과 아닌 것을 가른다 |

## 주의

- `build_region_master.py`는 KIKmix 외에 아무것도 읽지 않는다. 여기에 산출물 의존을 다시 넣으면 분리한 의미가 없어진다
- 산출물 결합은 **반드시 `행정동코드8`로** 한다. 이름 결합은 표기 차이 181건에 걸린다
- 행정동 개편이 발생하면 `LEGACY_MAP`에 추가한다. `check_region_coverage.py`가 "설명 안 되는 코드"로 먼저 알려준다
- 현재 `dong_matcher.py`가 `행정동_공식명_목록.csv`를 따로 만들고 있어 기준 데이터 출처가 둘이다. 기준표가 그 정보를 전부 포함하므로 정리 대상이다
