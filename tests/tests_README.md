# tests

`web/`·`src/` 의 계산이 어긋나지 않는지 검사한다.

## 왜 있나

2026-09-06 에 같은 총부담 계산이 세 군데에 따로 적혀 있어서 같은 조건에
3페이지 141.6만 / 5페이지 139.4만이 나왔다. 산식은 통합했지만
같은 종류의 사고가 다시 나지 않게 하는 장치가 필요해 2026-09-07 에 붙였다.

해석과 상세 기록은 `docs/pytest-results.md` 참고.

## 구조

```
tests/
├── conftest.py                  공통 픽스처. 소스는 utf-8-sig 로 읽는다(BOM 대응)
├── test_harness.py              카나리아. import 가 되는지만 본다
├── consistency/                 같은 것이 어긋나지 않는가
│   ├── test_monthly_purity.py   _monthly 가 맥락값을 인자로만 받는가
│   ├── test_app_wiring.py       app.py 가 네 페이지에 같은 인자를 넘기는가
│   ├── test_no_undefined_names.py  정의 안 된 이름·BOM (pyflakes)
│   └── test_cross_page.py       네 페이지 총부담 일치·반응  [db]
├── unit/
│   └── test_param_sync.py       파일 간·DB 간 파라미터 값 일치
├── policy/                      (예정) 정책 매칭 판정
└── db/                          (예정) 조회 계층
```

## 실행

```bash
pytest -m "not db"    # DB 없이. 1초. 개발 중에는 이것으로 충분하다
pytest                # 전체. 45초. 커밋 전에 한 번
pytest -rP            # 참고용 출력까지 본다
```

`db` 마커가 붙은 것만 MySQL 이 필요하다.

## 규칙

- **검사는 계산에 묶고 화면에 묶지 않는다.** 각 페이지는 계산 결과를
  `data["_calc"]` 에 남긴다. 화면 문자열을 파싱하면 템플릿만 바꿔도 깨진다.
- **`_calc` 는 계산이 끝난 직후에 남긴다.** 페이지 함수는 조기 return 이 여럿이라
  함수 끝에 두면 일부 경로에서 값이 안 남는다.
- **일치만 보지 않는다.** 네 페이지가 똑같이 입력을 무시하면 값은 일치한다.
  입력을 바꿨을 때 전부 움직이는지(반응)를 함께 본다.
- **안 터지는 지적은 실패로 만들지 않는다.** 미사용 import 같은 것까지 빨간불이면
  정작 중요한 실패를 무시하게 된다. 참고 출력으로만 남긴다.
