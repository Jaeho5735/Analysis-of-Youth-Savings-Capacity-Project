# web — LOCA 서비스

청년 1인가구 주거·통근 통합부담 분석 결과를 보여주는 Flask 앱.

강의에서 제공된 정적 HTML 시안과 Flask 뼈대를 받아, **라우팅·조회 계층·DB 결선을
직접 구현해 동적 서비스로 만들었다.** 화면 디자인의 출처는 시안이고, 값을 만들어
넣는 부분은 이 폴더와 `src/db/`가 담당한다.

실행 방법은 `docs/WEB_실행방법.md` 참고.

## 구조

```
web/
├─ app.py            Flask 진입점. 페이지 라우트 6 + 조회 API 1
├─ service.py        DB 조회 결과를 화면 JSON 구조에 주입하는 어댑터
├─ resolve_place.py  역명·건물명·주소를 행정동으로 해석(카카오 로컬 API)
├─ templates/
│   ├─ partials/     상단바·하단바·채팅바 공통 조각
│   └─ index.html, page2~6.html
├─ static/
│   ├─ loca_common.css   전 페이지 공통 토큰·상단바·하단바·입체감
│   ├─ loca_combo.css    자동완성 드롭다운
│   ├─ loca_combo.js     자동완성 + 페이지 간 입력 전달
│   ├─ images/
│   └─ loca_data.json, loca_page2~6_data.json
└─ uploads/          시안 원본 이미지(참고용, .gitignore 대상)
```

> **preview\*.html 은 제거했다.** `templates/` 와 같은 화면을 정적으로 복제한
> 파일이었는데, 두 벌을 유지하면 한쪽만 고쳐 화면이 갈라진다. 지금은
> `templates/` 가 유일한 원본이다.

## 라우트

| 경로 | 템플릿 | 값의 출처 |
|---|---|---|
| `/` | index.html | JSON 고정 (분석 요약 배지) |
| `/diagnosis` | page2.html | 입력 폼. 재방문 시 직전 입력 복원 |
| `/result` | page3.html | **DB 조회** — 현재 부담 진단 |
| `/explore` | page4.html | **DB 조회** — 후보 검증 + 추천 3곳 |
| `/explore/result` | page5.html | **DB 조회** — 현재 집 vs 후보 상세 |
| `/compare` | page6.html | **DB 조회** — 4열 비교표·차트 |
| `/api/suggest` | (JSON) | **DB 조회** — 입력 자동완성 |

입력이 없으면 각 페이지는 시연용 JSON 기본값을 그대로 보여준다. 서버가 죽지
않게 하려는 것이지만, **그 경우 "예시 화면입니다"를 화면에 밝힌다.** 조용히
기본값을 보여주면 사용자가 자기 입력 기준 결과로 오해한다.

## 입력이 페이지를 따라간다

2페이지에서 한 번 받은 값을 3~6페이지가 계속 쓴다.

```
거주지 · 근무지 · 만 나이 · 보증금 · 월세 · 출발시간 · 월 출근일수
```

전달 방식이 두 층이다.

1. **서버** — 각 `build_page*` 가 쿼리스트링을 만들어 CTA·네비 링크에 심는다
2. **브라우저** — `loca_combo.js` 가 페이지의 모든 내부 링크와 GET 폼에
   현재 입력을 다시 붙인다

2층이 필요한 이유는, 링크가 템플릿·JSON·partial 여러 곳에 흩어져 있어서
서버에서만 고치면 한 곳을 놓치는 순간 파라미터가 사라지기 때문이다.
실제로 상단 네비게이션에서 그 사고가 났다.

## 입력 해석 — 무엇을 쳐도 된다

`resolve_place.py` 가 카카오 로컬 API로 아래를 모두 행정동으로 옮긴다.

```
신사샤르망S 오피스텔   건물명
삼정KPMG              상호·회사명
시청역                 지하철역
테헤란로 152           도로명
상계2동                행정동
```

자동완성은 보조 수단이다. 두 글자부터 `/api/suggest` 를 호출하고, 목록에 없는
값을 직접 쳐도 통한다.

**자동완성 범위는 좁혀서 준다.** 경로 데이터가 거주동별 누적 80% 목적지까지만
있어서(거주동당 평균 72곳, 427개 중 약 17%) 전체를 열어두면 사용자가 없는
조합을 고르고 결과 화면에서야 실패를 알게 된다.

- 근무지 칸 → 입력된 거주지에서 **갈 수 있는** 근무지만
- 후보 칸(4·5페이지) → 입력된 근무지로 **갈 수 있는** 거주지만

## 데이터 흐름

```
app.py  →  service.py  →  src/db/query_dong.py  →  MySQL
                      ↘   web/resolve_place.py  →  카카오 로컬 API
```

`service.py` 는 템플릿을 수정하지 않는다. **기존 JSON 구조의 해당 자리에 값을
덮어쓸 뿐이다.** 화면 구조가 바뀌어도 JSON 키만 맞으면 코드는 그대로다.

### service.py 가 하는 판단

**① 현재 집은 사용자 입력, 후보는 동네 중앙값**

현재 집 주거비는 입력한 월세·보증금으로 계산한다. 그 동네 중앙값을 쓰면
3페이지에서 "총부담 129.6만원"을 본 사람이 5페이지에서 같은 집을 "106.2만원"으로
보게 된다. 대신 **기준이 서로 다르다는 사실을 화면에 밝힌다.**

**② 결론은 4분면으로 정한다. "월세 착시"를 고정해두지 않는다**

| 주거비 | 총부담 | 결론 |
|---|---|---|
| ↓ | ↑ | 월세 착시 |
| ↓ | ↓ | 실질 절감 |
| ↑ | ↓ | 숨은 효율 |
| ↑ | ↑ | 종합 부담 증가 |

**③ 경로가 없으면 인근 근무동으로 대체하되, 반드시 밝힌다**

경로는 전체 조합이 아니라 흐름 상위 80%만 있다. 없다고 화면을 비우면 다섯 중
한 명은 아무것도 못 본다. 같은 자치구 → 같은 권역 순으로 대체하고
"남영동은 경로 자료가 없어 같은 용산구의 한강로동 기준으로 계산했어요"를 띄운다.

**대체는 "현재 집 통근시간"을 구할 때만 쓴다.** 추천과 후보 검증은 사용자가
입력한 원래 근무지로 조회한다. 대체 코드를 추천까지 끌고 가면 화면은
"서울역 출근"이라 해놓고 실제로는 다른 동 기준으로 뽑아 값이 어긋난다.

**④ 요금 결측은 0이 아니라 정기권 상한으로 채운다**

0으로 채우면 "교통비가 안 드는 동"이 되어 부담 순위 최상위로 잘못 올라간다.
대체한 동은 플래그로 남겨 해석에서 걸러낸다.

**⑤ 혼잡도가 없으면 그 자리에 지역 진단을 넣는다**

혼잡도는 시연 경로 하나에만 있다. 빈 상자를 두느니 이미 조회한
부담유형·행정동 유형·시간가치를 사용자 언어로 풀어 4장으로 보여준다.

## 만 나이와 정기권

2026-09-01 기후동행카드가 **모두의카드**로 대체됐다. 정액형은 기준선을 넘는
금액을 100% 환급하므로 계산상 기준선이 곧 실질 상한이고, 기존 캡 산식을
그대로 쓴다.

| 만 나이 | 기준선 | 화면 |
|---|---|---|
| 19~39세 | 55,000원 | 청년 대상. 환급률 30% |
| 그 외 | 62,000원 | 일반 기준. 환급률 20% |

값의 원천은 `data/정기권_가정.csv` 다. 같은 파일을 `src/db/load_to_db.py` 가
`dim_transport_pass_assumption` 에 적재해 CSV·DB 가 같은 값을 본다.

## 값이 왜 그렇게 나왔는지 밝힌다

계산이 맞아도 설명이 없으면 틀린 것처럼 보인다. 3페이지 경로 카드 아래에
접이식으로 넣었다.

```
주거비 77.9만원 = 월세 75만원 + 보증금 1000만원을 월로 환산한 2.9만원
                 (전월세전환율 3.48% 적용)
교통비 5.5만원  = 실제 이용액은 월 6.9만원이지만, 모두의카드 청년(55,000원)을
                 쓰면 여기까지만 내요
통근시간 가치   = 실제로 내는 돈이 아니라, 길에 쓰는 시간을 최저임금으로
                 환산한 값이에요
```

## 알려진 제약

**역 이름은 표시하지 않는다.** `fact_commute_route` 에 노선·환승횟수는 있어도
승하차역 시퀀스가 없다. 경로 띠는 실제 노선색을 쓴 수단·노선 순서로 채우고
"역별 상세는 보유하지 않아 이용 수단 순서로 표시했어요"를 명시한다.

**혼잡도는 잠원동 → 역삼1동 조합에만 있다.** 팀원이 그 경로 하나에 대해서만
TMAP 칸별 혼잡도를 수집했다. 다른 조합은 지역 진단 카드로 대체된다.

**업무지구가 아닌 근무지는 경로 커버리지가 낮다.** 시연에는 역삼1동·여의동·
소공동 같은 업무지구를 쓰는 편이 안전하다.
